## 已收敛与保留项

不阻塞实施的未决项：初始 soul / 经历材料留空；soul 自动修改默认关闭，仅记录候选；不实现物理删除。预算、合批和空闲间隔采用有界可调默认值，不新增产品审批。

核心代码不依赖 Harness；原生记录、恢复、模型路由、能力与生命周期位于 `src/adapters/harness/`。不另建权威记忆数据库。Markdown 为接受版本的投影，丢失时由日志重建。默认关键词 / 中文字符片段检索，不预设向量服务。

## 验收要求

来源不可伪造；提交版本冲突和重复不覆盖新结果；保存失败不发布缓存；主线不能编辑 narrative 或访问宿主工具；整理模型看不到未授权工作区；重启恢复整理进度与叙事；遗忘 / 更正不被旧召回或上下文绕过；新段不丢发送回执。使用合成模型测试，不消耗真实 API。

## 实现落点

- `schema.ts` / `store.ts`：有来源的经历、思考 / 意图、任务、记忆变更、叙事与交接；纯折叠、版本冲突、去重、保护和召回过滤。
- [宿主记忆适配](../../adapters/harness/memory.ts)：一个长期整理 Agent / Session，增量 / 反思 / 维护对话串行，独立云端上下文和能力，复用宿主模型路由。
- [主线运行时](../../adapters/harness/runtime.ts)：按产品时区安全换段，跨段聊天与发送回执恢复，接入 L0–L4 和主线窄工具。
- [压缩适配](../../adapters/harness/compaction.ts)：私有 Agent 作用域内调用原生 token meter / compaction-basic；先保存原文来源，再检查压力，模型溢出最多恢复一次。压缩生成有限工作摘要，不写 narrative。
- [面板](../../client/panel.tsx)：右上角聊天菜单展示每日主线，整理菜单可选择 / 新建独立维护会话，原生设置弹窗指定自动任务投递 Session，主线旧段只读，主线 / 整理线各自保留草稿；沿用 DSH 公开控件与样式，不增加记忆管理列表或上部品牌栏。[输入适配](../../client/composer.tsx) 通过固定版本 / 哈希的本地构建桥复用原生 InputBar 和输入机，不绑定普通工作区；权限插槽不挂载。
- [Remote 契约](../../adapters/harness/remote-contract.ts) / [服务](../../adapters/harness/remote.ts)：复用原生 Gateway 和 WebSocket，移除旧 HTTP 轮询，保持专属 Session 身份校验及发送回执。

## 原生持久承载

当前 v4 格式要求模型对话有受保护的 system head 和真实 turn / step，公开 `Session.append` 又不能为自定义事件附加 ignorable 标记。首版没有伪造 turn 或借用其他插件事件：

- `sessions/`：主线各日期段的原生日志。
- `memory-sessions/` 下默认 `liveseed-memory`，用户可按文档 14 登记 / 指定其他专属 Session：同一时刻串行执行一个任务；自动任务走指定会话，用户维护对话可使用其他本域会话，按长期 Session 恢复，保存调用、原生 reasoning、维护对话和工作压缩。
- 同一私有持久服务下 `liveseed-memory-journal`：**不创建 Agent、不调用模型**的原生审计 Session。通过公开 persistence write handle 追加原生 `user/message`，以独立 source 保存代码提交记录；不注入任何模型。它是 Session 日志集合的一部分，没有另建权威数据库，也没有第二条整理线。
- `narrative.md`：仅渲染已提交 L1；删除或篡改后在启动时由审计日志重建，不重跑模型猜历史。
- `soul.md`：可选初始人物材料导入槽，首次提供和后续人工改动按来源留版本；未提供则为空，文件暂时缺失时可恢复已接受版本。整理模型只能记录 soul 候选。

提交先校验版本 / 来源 / 范围，再追加并 flush 原生日志，最后发布内存视图和 Markdown。失败停止后续写入；重启以已存日志恢复。整理任务记录独立来源和意图覆盖位置；取消的维护任务不会重启后自行重放。

## 时机与默认预算

默认每积累 8 条原始话语来源，或输入停止后 60 秒，合批整理；每 4 个接受批次进入反思，重要 / 理解意图优先触发反思。用户维护对话在当前任务结束后优先处理。任务写入承担者 ID，手工更换整理 Session 不迁移旧任务或清空记忆域；未结束自动任务留在原承担者，恢复指定后再处理；任意登记会话的维护对话可继续处理，不改变后台任务目标。参数为 `memoryBatchSize`、`memoryIdleMs`、`memoryReflectionEvery`；整理输出上限 `memoryMaxTokens` 默认 4096。失败保留任务，60 秒后可重试，不重复提交已经接受的操作。

主线每次原生 turn 最多 6 个模型步骤，主动补查最多 4 次，总记忆工具调用最多 8 次；临时保护 24 小时且主线不能对同一来源反复续期。L3 默认最多 6 条、约 6000 字符的结构化材料，原话可以按 ref 分页展开。长期保护和生命周期由整理线处理。

模型配置 `memoryProvider` / `memoryModel` 成对提供；省略时沿用宿主默认路由。按产品约定应在宿主选择 DeepSeek，或显式绑定已有 DeepSeek 路由；代码不猜测供应商别名，不复制凭据。主线和整理线可以同型号，调用上下文与能力仍分别隔离。

## 验证与限制

`pnpm check` 验证来源伪造、保护、版本冲突、接受去重、主线主动召回 / 理解记录、维护对话、归档后的 Context 撤回、Markdown 重建、跨日回执、长期整理 Session 压缩恢复、原生压力压缩及溢出恢复、未完成任务恢复、取消和保存失败。`pnpm test:browser` 使用隔离 DSH_HOME 验证入口切换、维护与主线恢复、认证以及普通列表 / 搜索隔离。

本次结果与证据范围见 [验收记录](../../../docs/validation/liveseed-memory-2026-11-06.json)。

这些验证使用合成模型。真实 DeepSeek 整理质量、长 soul 的实际窗口占用、超长日志恢复性能尚未实测；检索首版为内存投影，未引入向量服务。其他工作区 prompt 观察与 15 秒主动表达属于后续模块，尚未接入；视觉仍只预留接口。
