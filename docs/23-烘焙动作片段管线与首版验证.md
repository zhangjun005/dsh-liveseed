# 烘焙动作片段管线与首版验证

日期：2026-11-07。状态：**管线已实现并通过自动验收；动作质量未通过，需要校准**。设计依据见 [21](21-动作衔接与AI关键帧方案.md)、[22](22-动作语汇与首版清单.md)、[20](20-动作生成路线调研.md)。

## 实现了什么

| 环节 | 落点 | 说明 |
|---|---|---|
| 制作 | `scripts/authoring/bake-vmd.mjs` | 读 VMD，按 MMD 贝塞尔插值在 30fps 采样，输出 `src/client/character/clips.generated.ts`；记录 VMD / MPL 的 sha256、工具版本与许可 |
| 数据语义 | `src/client/character/clips.ts` | 旋转是**绝对局部旋转**；`mask` 是完整控制集；`reference: 'clip-first-frame'` 明确"第 0 帧是片段自己的参考姿态，不是本模型校准后的待机姿态" |
| 运行时 | `pose.ts` 拆分 `restore → authored → applyClip` | 每帧仍先重建 authored 基线，再由片段按 mask 以权重 slerp 叠加；片段**不接管** AnimationMixer，也不是绝对覆盖 |
| 淡入淡出 | `applyClip` | 0.25s 淡入；到 `duration - 0.25s` 自动淡出；`stopClip()` 立即淡出；权重归零后释放图层 |
| UI | 设置 → 角色 | 「播放挥手片段」「停止片段」，用于人工验证 |
| 验收 | `scripts/testing/character.test.mjs` | mask 只含声明骨骼、帧数 = 时长×帧率+1、30fps 相邻采样连续性、越界钳制、叠加后回基线无漂移 |

许可边界：MPL 编译器（GPL-3.0）只在离线制作阶段使用，运行时不导入其代码；运行时只读烘焙后的数据。`mmd-parser` 作为制作期开发依赖引入。

## 自动验收结果

`pnpm check` 15/15 通过，其中新增：

- `baked clip keeps its mask, samples continuously and clamps at its duration`：67 帧 / 2.2s / 4 骨骼，相邻采样最大角步长 0.13 rad（初版时间轴过急时为 0.51 rad，已通过放慢抬手修复）。
- `clip layer blends over the authored baseline and releases back without drift`：片段驱动 `右腕`/`右ひじ`，释放后回到 authored 基线（误差 < 1e-4）。

## 真机验证：动作质量未通过

在隔离宿主加载真实 PMX 播放片段（`.local/clip-probe-*`，不提交）：

1. 第一次试摆：`arm_r bend forward 52` → 手臂只是向外下方伸展，不是抬手。说明 MPL 的语义方向必须针对本模型重新校准（其规则是通用人形假设）。
2. 第二次试摆：抬到 86–90° 并弯肘 → 手势形态对了，但**袖子被撑坏**：关闭物理时手臂直接穿出外套；开启物理时外套袖被拉出一个大片内翻面（粉色区域）。
3. 该模型的袖子、肩领、胸、裙摆都是**物理驱动骨**（332 根），是否穿模取决于物理与碰撞，不是单纯角度问题；单纯减小角度只能回避，不能解决"抬手时袖子怎么跟"。

结论：**管线成立，动作制作是当前瓶颈**。下一步必须在"姿态校准 + 袖子间隙"上迭代，而不是继续扩动作数量。

## 已知边界

- 片段数据是 30fps 采样；运行时在两帧间做线性 slerp，深究插值精度时需比较采样误差。
- `reference: 'clip-first-frame'` 意味着片段首尾姿态是 MPL 的 rest（零旋转），与本模型校准后的待机姿态不同；当前靠"淡入叠加"回避跳变，但**不能把片段当绝对姿态直接覆盖**。
- MPL 不覆盖捩骨、`肩P`/`肩C`、`両目`；视线与眨眼仍归自有层。
- 未验证：`wave-small + nod` 同播的浏览器表现、中途取消的视觉连续性、长时间物理稳定性。

## 2026-11-07 后续：按用户决定不使用物理（含一次误判修正）

用户明确表示该模型在原游戏中也没有怎么做物理，不建议加物理。本轮在**完全不加物理解算**的前提下重测（物理默认关闭）。

**先修正一次误判。** 此前判断"手臂离开袖子、袖子不跟随"，是错的。实测骨骼层级是：

```text
右ひじ(24) ← 右袖(139, 静态碰撞代理) ← 右袖1-1(140, 物理驱动) ← 右袖1-2
                                    ← 右袖2-1 … 右袖饰一 / 二
```

袖子本来就挂在 `右ひじ` 下；物理关闭时其子骨保持静止局部变换，因此袖子**随前臂刚性移动**，绑定成立，不需要重新绑定。空闲画面里袖口下端本来就露一小块粉色内衬；大幅抬手时袖口转向镜头，内衬被大面积看见，那是几何与朝向问题，不是穿模。

实测幅度：

| 幅度 | 结果 |
|---|---|
| 上臂 45°、前臂 50°、手腕 ±20° | 动作可见（与 idle 差约 6300 像素，待机噪声约 340），袖形正常、无异常露内衬 |
| 上臂 86–90°、前臂 52–72° | 袖口转向镜头，内衬大面积外露；不属绑定失败，但观感不可接受 |

当前 `wave-small` 采用 45° 版本（2.2s）。若想让手势更大又不露内衬，可选：给袖口骨加朝向补偿（物理关闭时这些骨可写）、用 Reze Studio 手工调前臂/手腕角度，或调整材质内衬。三种都不在本次范围内，需要时再定。
