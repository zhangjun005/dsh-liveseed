## 环境

Node.js `22.23.3`、pnpm `11.25.0`、DSH `0.2.0-rc.2`、Cordis `4.0.5`、Cordis loader `1.0.6`、TypeScript `6.0.3`。

## 检查

- 初始化前目标为空、不属于父级 Git 仓库；初始化后 Git 分支为 `codex/bootstrap`，无 remote，无旧项目配置与提交。
- `pnpm install` 成功；锁文件记录精确开发依赖与完整性哈希。
- `pnpm check`：类型检查、构建、真实 Cordis loader 导入、调用插件入口及卸载成功。
- `npm pack --dry-run`：检查包内编译入口、声明和 bundle；打包前自动构建，避免分发空壳。
- 使用项目 `.local/dsh-smoke-home` 作为临时 `DSH_HOME`，在 `sdk-minimal` 模板的独立检查 profile 上加载开发覆盖层；`--dump-config-schema` 成功且结果可解析为 JSON。这里只做配置检查，没有运行 SDK 服务，不代表产品采用 SDK 子进程架构。

## 已知的宿主检查限制

DSH `0.2.0-rc.2` 的完整 Web 模板 `--dump-config-schema` 报四条 `unrecognized Loader tree carrier`，位置 `/179` 到 `/182`。**不加 LiveSeed 覆盖层时也出现同样错误**，因此是本机现有 Web 模板与 schema 检查的兼容问题，不能归因于本插件。

未更改宿主代码以绕过检查，也未升级用户 DSH。完整 Web 启动、实际 Session、persona、权限和 UI 接入仍未验收；这些功能尚未实现。本次通过项只覆盖开发骨架与最小宿主组合。
