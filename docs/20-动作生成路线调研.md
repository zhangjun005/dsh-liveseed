# 动作生成路线调研

日期：2026-11-07。状态：联网调研与建议，未选型、未安装依赖、未下载素材、未在本机 PMX 上跑过任何一条。现有实现与验收见 [19](19-PMX常驻舞台首版与验收.md)，此前调研见 [16](16-AIRI接入与动作来源调研.md)、[17](17-上身动作与HAST行为控制复核.md)、[18](18-完整PMX骨架与表情适配方案.md)。

## 记录：当前方案

已在用并作为后续基线：

- 保留原始 PMX 的 493 骨骼与 84 Morph，不删骨、不重蒙皮、不转 VRM；执行器为 `@takahirox/three-mmd` 0.1.4 / Three 0.186.1，IK / 继承 / 物理走单条 MMD 更新链。
- `pose.ts` 是程序化姿态：呼吸、眨眼、视线、点头、挥手、侧倾、重心移动、单侧轻摆腿；手臂按实际肢段方向计算，每帧从 authored 基线重算。
- 计划中的扩展：HAST 的 53 骨骼标准控制空间经角色专用映射桥接入；面部用本模型的语义 Morph 配方；组合表情、口型、VMD 导入、主线表现意图均未接入。

## 用户提出的两条直觉

**"AI 手 K（AI 辅助关键帧）"**：有两条完全不同的实现路径。一条是外部 DCC 工具里用 AI 摆姿 / 物理辅助手 K，导出 FBX 再转 VMD；另一条是让大模型直接写出语义化的动作脚本，编译成 VMD。后者已经有人做出来了。

**"Live2D 用贝塞尔曲线控制，3D 可能不太行"**：结论是能，只是表现形式不同。Live2D 的本质是「参数（角度 / 呼吸 / 身体旋转）→ 贝塞尔曲线定义参数随时间变化 → 参数驱动网格变形」。3D 的等价物是「关节角度作为参数 → 曲线定义插值 → 骨骼通道 + 分层加法混合」，不需要网格变形那一层；three.js 的 `AnimationMixer` 原生支持 additive layer。所以 3D 不但能做，而且比 Live2D 更容易叠加多层（基础呼吸层 + 手势层 + 视线层互不覆盖）。

## 建议的组合

**运行期**：A 作为骨架 + 预烘焙片段库（由 B/C/D/E/F/G 任一产出）。所有片段统一成 AnimationClip 进同一个 mixer，按通道分层：基础呼吸 / 重心层、手势层、头部与视线层、表情层；手势按进入 / 执行 / 收回 / 中断淡出管理，只占其声明的骨骼。

**制作期**（按性价比排序）：

1. **B（LLM 写语义动作脚本）**：这是"AI 手 K"最贴合本产品的一条。主模型已经存在，让它输出受限的语义关节指令 + 时间轴，比额外跑一个动作模型轻得多，也天然符合 [12](12-Context内容层级与主线记忆权限.md) 的"主线有限表现意图"。落地时不复制 GPL 代码：要么把 MPL 的语法当作设计参考自写解析与曲线引擎，要么离线用 MPL CLI 把脚本编译成 VMD 再作为素材播放。
2. **C（Cascadeur）**：需要"好看一点点"的招呼、鞠躬、递东西这类关键手势时，手工做几个，导出 FBX → reze-rig → VMD。数量少、质量高。
3. **D（XR Animator / MiPo）**：自己对着摄像头录日常小动作（挠头、托腮、伸懒腰），直接出 VMD。日常感最好，且不外传模型。
4. **E（HY-Motion）**：有显卡时批量生成候选再人工挑；注意它不做原地循环，要自己裁首尾。

**面部分支**：J。先用实际音频事件驱动口型 Morph，再做组合表情配方。

**暂缓**：H（HAST 重定向）。等有足够多已验证动作素材，再判断是否值得引入它的求解器。

## 硬约束

- **GPL-3.0（PoPo / MPL / reze-engine）不得直接并入插件代码**，否则整个插件要按 GPL 发布。离线工具使用、语法参考、输出数据（VMD 文件、MPL 文本）是不同的问题，需要逐项判断。
- **模型资产不上传第三方云端**：QuickMagic、Rokoko Vision 这类云服务会把视频/模型传上去，与本模型"禁止二次配布"的使用协议冲突，只能对通用人形源素材使用。
- **许可风险**：HY-Motion 区域排除条款、Cascadeur 版本分级、MMD 动作库的商用与二次配布条款，都要在实际采用前核对。
- 表现状态仍然不写回长期情绪 / 记忆；后台整理不触发播放；主线表现意图必须受限并经校验。

## 未验证

- 以上工具均未在本机运行；MPL 的语义骨骼子集（body core / 双臂 / 双腿 / 手指）能否覆盖本模型的实际控制链未验证。
- 各路线输出的动作在 493 骨 PMX 上的骨名、参考姿态、体型与服装适配均未实测。
- 性能与常驻开销未知，不能把单次生成或短时播放当成全天可用。
