前端更新（2026-11-07）：每日主线段已在聊天导航中展示，当前整理通过独立按钮直达；手工指定整理承担者位于设置，历史只读；实时通信走原生 Remote / WebSocket。具体见 [13](13-专属会话导航与原生通信.md)。

日期：2026-11-06。分段、有限交接和跨段回执恢复已接入首版，通过合成模型恢复测试；实现与限制见 [记忆模块说明](../src/core/memory/README.md)。旧原型的 `liveseed-main` 可作为第一段继续恢复，新段在输入的安全边界创建。

## 对 Session 的理解

DSH 的常见使用方式将 Session 用于一份工作，但本机 `0.2.0-rc.2` 的 Session 类型将它定义为带有 surface 的 append-only 事件日志，Agent API 支持 create / resume。没有从所核对接口发现固定的日时限或“一个任务结束必须销毁”的契约。

因此可以长期使用同一个 Session；目前没有测试证明它能在任意事件规模下维持固定成本。context 压缩缩短模型可见 surface，原始日志仍增长。Session 实例持有日志，恢复会处理已存事件，长日志的恢复、投影与常驻成本应单独测量。

## 已确认的三层

| 层 | 生命周期 | 负责什么 |
|---|---|---|
| 德谬歌的逻辑身份与记忆域 | 跨天、跨日志段 | 相同身份、关系、叙事、记忆取舍、有效承诺与授权 |
| 原生对话 Session | 按天或其他边界分段 | 一段实际经历、工作 surface、原生 agent 生命周期与恢复 |
| 面板聊天与记忆投影 | 按需要展示与查询 | 连续聊天，可按日回看；不要求用户进入每日独立聊天窗口 |

身份不再用某一个 Session ID 表达。所有原生 Session 仍在同一私有运行域中，不进入宿主普通工作区。只保持当前需要的对话 Agent 活跃，读取旧日志不等于重新运行旧 Agent。

唯一事实源由“单个 Session 日志”扩展为“属于同一记忆域的一组原生 Session 日志及其中已提交的交接 / 记忆决定”。这没有增加另一份权威事件库；跨段索引、当前段指针和 L1 `narrative.md` 都应可由已提交记录恢复。L0 soul 是独立版本化的底层人物材料，保留原始材料与有效变更记录，不再用这个名称指代积累的自我叙事。具体记忆操作的原生持久承载仍需验证，不因分段而跳过。

## 默认按天轮换

本节轮换对象仅为主对话 Session。整理线长期保留同一个私有 Session，不随主线换日；允许用户手工指定承担者，见 [14](14-整理Session指定与界面设置.md)。任务、压缩与权限的对应关系见 [12](12-Context内容层级与主线记忆权限.md)。同一记忆域因此同时包含主线日期段和长期整理日志，来源与记录类型仍须区分。

按产品时区 Asia/Shanghai 标识日期，按安全边界轮换，不在午夜强制打断生成：

- 到新日期后，在首条新消息发送前检查日期，当前轮次已结算、Agent 空闲且交接可恢复时换段。当前不做话题结束判断，也不由午夜定时器主动换段。
- 新输入只能进入一个确定的活动段，轮换与输入接收必须串行协调。换段期间已接受的输入不得丢失或重复执行。
- 没有活动时不必为每个日历日创建空 Session；下一次活动时再决定日期归属。
- 当前没有消息量阈值或手动新建主线的入口，同一天继续同一段，接近窗口时走段内原生压缩。未来可按容量同日分段，但尚未实现。
- 日期命名可示意为 `liveseed-talk-2026-11-06-01`，但日期字符串不能代替唯一 ID、活动状态和恢复协议。

跨零点仍在旧段里的事件保留实际时间，进行中的回复继续写原段；当前目录按 Session 的日期标签分组，不把段内消息重新拆成自然日视图，不假定所有事件一定同属命名日期。重启和时钟变化不能只凭当前日期误开第二个活动段。

## 新段如何接上

新段所需内容应有限、带版本与来源；区分长期层的直接加载与本次交接：

1. 直接加载当前 L0 `soul.md` 与 L1 `narrative.md`；后者承载积累的自我理解、关系地基和有效取舍，不把它们再全文抄入当日交接。
2. 交接 L2 中尚未结束的话题、临时未完成事项，以及当前必须承接的约定。
3. 交接必要的近期原话与简短工作摘要，避免连续聊天突然丢失语境；具体历史记忆仍由 L3 按需检索。
4. 当前处境、实际时间与必要活动背景，以及来源段和整理覆盖位置等内部引用；不恢复独立情绪数值。这些运行字段不必都交给主模型。

各自的授权和访问限制继续生效。内部轮换不是角色“今天失忆 / 重新认识用户”的情节，也不要求主线说醒来或宣布换房间。主线自然接续已经形成的记忆视图。

不建议每日以完整 fork seed 复制全部过去：本机 fork API 继承日志前缀，会抵消限制单段增长的目的。应新建原生 Session，通过受支持的原生上下文准入携带有限交接；原生 `parentSession` 是 fork lineage，不能随意借作业务前后段关系。

## 整理、压缩和换段如何分工

| 操作 | 原因 | 作用范围 |
|---|---|---|
| 段内 context 压缩 | 当前模型输入接近窗口 | 改变当前 Session 的工作 surface |
| 按日 / 按需换段 | 限制单段历史规模、便于生命周期与归档 | 新建日志段并交接有限工作上下文 |
| 增量整理与低频反思 | 提炼经历、维护理解和自主取舍 | 同一身份的跨 Session 记忆域 |

换段可以触发旧段未整理范围的优先处理，但不要求先完成整日反思或全部遗忘决策才能换段。前提是原文可恢复、整理任务不丢失、当前对话的交接内容可用。若连最小交接都不能可靠建立，则推迟轮换，继续旧段并按需要压缩，不空白启动新段。

整理任务绑定创建时确定的来源 Session 与事件集合。切换后，不得将“当前活动 Session”替换成任务原来的来源。旧段任务可以稍后完成，并在记忆提交域核对版本后生效；其产物不应因旧 Agent 已释放而丢失，也不自动改写成今天的新经历。

证据引用至少是 `(sessionId, eventSeq)`，不能只存 seq 或日期。复制进新段的交接是派生内容，不得重新作为独立经历抽取；新段还应保留来源引用以防重复强化记忆。

## 轮换的持久化与崩溃恢复

需要单一接收输入的活动段，以及可从日志判定的轮换状态。大致过程：旧段结算并 flush → 准备有限交接与候选新段 → 持久化可恢复的激活关系 → 切换输入归属 → 释放旧 Agent。

当前已按此顺序实现，不假定多个 Session 文件能原子提交。候选段尚未激活时不接收输入；恢复不能只按最新文件或日期猜活动段。仅作为缓存的活动段指针损坏后仍应能从有效日志重建。

还要保留跨段发送去重：当前回执以实际原生记录恢复，并合并旧段回执查询；接受过的相同 UUID / 内容可以确认，不能在旧段借重试写新消息。

## 当前代码与验证边界

- `src/adapters/harness/runtime.ts`：启动时恢复审计记录中最后激活的主线段；无历史时创建首段 `liveseed-main`。每次实际发送先查跨段回执，再检查空闲 / 模型准入，然后按 `productDay()` 决定是否轮换。
- `src/adapters/harness/memory.ts`：`productDay()` 固定 Asia/Shanghai；原生审计持久化日期、段身份和有限交接；整理从原始日志摄取事实，保持跨段来源。
- 新段 ID 为 `liveseed-main-YYYY-MM-DD-UUID`，旧段 flush 后补摄取来源，新段 flush、审计激活成功后才替换活动 Agent，随后释放旧 Agent。L0 / L1 独立加载，L2 交接近期最多 8 条、每条至多 1600 字符的带来源材料及当前章节，L3 仍按需召回；不会复制全部旧 Context。
- `src/adapters/harness/transcript.ts`：活动段展示和已接受回执可由原生日志重建，重启读取历史回执；打开历史通过只读 persistence handle，不恢复旧 Agent。专属 Session 不进入普通工作区。
- `src/client/panel.tsx`：聊天按钮列日期段，“聊天”指向逻辑 `current`，实际换段时通过原生流更新，草稿保持；历史只读。用户当前是否正在回看旧段不改变实际发送的活动段。
- 已通过合成原生 Session 跨日换段 / 交接 / 回执恢复和隔离浏览器昨日 / 今日导航验收。没有声称已覆盖任意事件规模的恢复成本或所有跨文件故障点。

## 后续验证

1. 跨日轮换后，主线能接续未结束话题与已接受记忆，界面连续。
2. 午夜生成中不被中断，待处理输入准确归属，旧 Agent 释放。
3. 整理任务跨段完成，来源不串、提交不覆盖新版本、交接不重复抽取。
4. 候选创建、激活与旧段释放的不同故障点恢复后，仍只有一个接收输入的活动段。
5. 跨段重试不重复生成；旧日志可查且不进入普通工作区。
6. 同一天超量、无活动跨多天、重启和日期变化下，分段策略仍可恢复。
