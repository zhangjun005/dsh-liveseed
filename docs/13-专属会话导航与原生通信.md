# 专属会话导航与原生通信

日期：2026-11-07。针对“模式按钮掩盖真实 Session 结构、输入与通信过于自建”的修正。按用户后续要求，会话导航收起为右上角依次排列的聊天、记忆整理、设置圆形按钮，并接入原生 InputBar 与原生编辑器 / 提交状态机。

## 会话结构在前端可见

- 德谬歌面板内有独立会话导航。“聊天”下按日期列出真实主线 Session；同日多个段显示序号；当前段标记为“当前”，历史段仅回看，不恢复或唤醒旧 Agent。
- “聊天”指向逻辑当前段。发生安全换日后，服务端活动段变化通过流推送，当前视图随之切换；人格、记忆域、跨段来源和发送回执延续。
- “记忆整理”默认使用 `liveseed-memory`，没有日分组，不按任务新建 Session。按用户后续澄清，允许手工指定承担者，协议和恢复语义见 [14](14-整理Session指定与界面设置.md)。
- 原生审计 Session 不出现在导航中，也不能通过消息 API 打开。这里是会话导航，不是记忆条目管理页。
- 专属会话仍不注册到普通工作区的列表、搜索或 Controller；复用输入外观不意味着获得工作区权限。
- 不新增上部品牌栏或产品内左侧栏；桌面和窄屏均通过右上角聊天按钮展开日期列表，整理按钮展开独立会话列表，设置按钮打开原生 Modal 分类弹窗来指定自动任务 Session，点击外部或 Escape 收起。草稿按对话入口保存，切换主线 / 整理线与重连均不清空另一侧草稿。

## 原生通信路径

旧 `src/adapters/harness/http.ts` 与 `/liveseed/api/*` 路由已移除。前端不再自行 `fetch` 或按 500ms 周期轮询。

调用与推送走 DSH 的 `TypertRemoteService`、严格 InvocationDescriptor、Gateway、Connection 和 WebSocket 复用通道，使用相同认证、Host/Origin 检查、错误信封与重连生命周期。业务边界位于独立 `liveseed` namespace：

| 方法 | 用途 |
|---|---|
| `catalog` | 只列本产品日期段、当前指针及整理候选和当前承担者 |
| `snapshot` | 已授权专属会话的有限展示；历史通过只读 persistence handle 读取 |
| `follow` | 原生逻辑流，先 baseline，后目录 / 消息 / 流式文本更新 |
| `send` | 当前主线或整理会话发送；保留 UUID 回执去重，拒绝向旧段追加新消息 |
| `stop` | 只取消本产品当前回复或整理任务，不能控制普通工作 Agent |

`current` / `memory` 是本 namespace 的逻辑当前主线 / 整理地址，返回值仍包含实际原生 Session ID。活动段切换和视图读取经过同一输入串行边界，目录与消息不拼接成不同段。视图变更键包含 generation、Session ID、revision 与只读状态；不能仅比较 seq，因为不同 Session 可以具有相同 seq。

流取消会释放订阅。客户端使用原生 `remote.$stream`，重连以 baseline 重建，保留草稿和未确认请求 ID；流式更新不反复发送全部聊天记录。历史段只允许确认已存在的相同发送回执，不能借重试追加新内容。载荷严格拒绝夹带 cwd、工具或其他工作区 / 审计会话身份。

## 输入组件复用的实际边界

实际复用 DSH 原生 InputBar、SessionInputShell、Lexical 编辑器、键盘处理、撤销和发送失败草稿恢复。权限插槽直接不挂载，Plan、普通工作区命令和附件也不授予；原生未启用的指令按钮保持禁用。没有自建 textarea 或模拟输入样式。Button / MarkdownText 和主题仍使用宿主组件。

`0.2.0-rc.2` 尚未公开独立 InputBar / 输入机的值导出。按用户明确要求接入原生输入框，本次采用**限定版本的本地构建适配**：从 npm 已发布的公开 `/client` bundle 入口读取原始实现，核验完整 SHA-256，在独立 ModuleLoader factory 中导出同一份 InputBar 和 SessionInputShell。必须一起复用，以免不同 Lexical 实例混用。适配位于 `scripts/build-client.mjs`、`src/client/native-composer.d.ts` 和 `src/client/composer.tsx`；不是已获上游保证的稳定公开 API。

构建期锁定 conversation `0.2.0-rc.2`，bundle SHA-256 为 `8d5c8223197d52d69eb0587f88a8a051fc172985553915f1de361544653a68b0`；上游变化时构建失败，重新审查后再升级，不静默退回自建编辑器。分发包含 DeepSeek MIT 许可 `dist/NATIVE-COMPOSER-LICENSE.txt`。原生样式随原始 bundle 加载。

不调用复制 factory 的 `apply()`，不改写全局安装或全局 Sessions。每个逻辑聊天入口拥有独立的本地输入机，私有 sink 仅调用 `remote.liveseed.send`；不绑定普通 Session Controller，不借用工作区草稿。主线安全换日保持当前入口草稿，整理草稿按实际查看的 Session 分开；每日历史只读、两个入口切换及重连均保留各自输入机。面板卸载释放编辑器和 Context。

## 依赖与验收

主线与记忆业务保持 [08](08-长期身份与Session分段.md)、[10](10-Context状态与工作输入触发.md)、[12](12-Context内容层级与主线记忆权限.md) 和 [模块说明](../src/core/memory/README.md) 的边界。新增 Gateway、Typert protocol / registry 与 UI primitives 依赖均锁定 `0.2.0-rc.2`，没有扩大 Harness 兼容范围。

`pnpm check` 包含原生业务回归、Remote 历史只读 / 外部身份拒绝 / 取消和不同 Session 同 seq 的回归测试。`pnpm test:browser` 在隔离 DSH_HOME 中创建昨日来源，验证新日真实换段、两个日期视图、唯一自动任务投递 Session、独立整理会话及手工指定、原生 WebSocket follow、无需刷新页面的宿主重连、草稿保留、认证与普通列表 / 搜索隔离；断言前端没有调用旧轮询端点，并检查真实 Lexical DOM、圆形按钮位置、浮层关闭、原生 Enter / 换行 / 撤销和失败草稿恢复。全部使用合成模型，不消耗真实 API。验收结果见 [记录](validation/liveseed-ui-2026-11-07.json)。
