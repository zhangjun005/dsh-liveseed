# Context 状态、整理对话与工作输入触发

实施更新：记忆 Context、独立整理对话和宿主模型路由已接入首版，见 [模块说明](../src/core/memory/README.md)。其他工作 prompt 观察与 15 秒主动表达仍未接入，不能将二者混为已实现。

日期：2026-11-06。状态：用户给定的最新产品方向与接口核对记录，尚未实现。与此前独立数值状态、记忆管理页或固定作息发言的候选冲突时，以本文为准。

组装内容按本文保留；soul 与叙事的分工、避免硬性语气指令的具体组织方式见 [叙事续接方案](11-叙事续接式Context与表现协议.md)。动作仅预留接口，不恢复视觉模块实施。

## 用户已明确的取舍

- 不另做独立的情绪 / 关系数值状态模块，状态依赖 context。
- 不做复杂的记忆管理入口，允许用户直接与整理记忆的线对话。
- 最初始记忆只预留位置，不在本阶段填入整套剧情或人格经历。
- 每天首轮使用已经确认的跨段有限交接，不重新讨论是否清空身份。
- 主动表达在用户于其他工作文件夹的 DSH 会话提交 prompt 后 15 秒触发检查；情绪线索和连续工作较久只能影响这次检查，不构成独立触发源。
- 整理使用 DeepSeek，走 DSH 的接入接口，不新增独立云端 HTTP 客户端或复制凭据。
- Live2D / 3D 继续搁置，仅预留接口。

## Context 中的状态

主线从真实近期对话、记忆叙事、当前时间和允许的工作活动背景理解处境。没有独立 `valence / arousal / trust` 状态表、更新系数或定时衰减，也不通过“今天没来，信任下降”等规则赋予情绪。

后台仍需要任务进度、请求去重、活动时间和取消标记；这些是运行事实与可重建指标，不是另一个人格 / 情绪状态模块。情绪波动只作为措辞与近期上下文提供的线索，不将模型猜测写成用户已经被确认的情绪事实。

## 用户与整理线对话

在同一专属面板提供一个简单的整理对话入口，具体呈现可采用模式切换；不要求用户学习记忆列表、分值和生命周期按钮。

用户可自然地说“这件事不用再提”“把今天聊的整理一下”“你记住了哪些关于这件事的内容”。整理线用自己的上下文答复，必要时提出记忆维护候选，仍由既有来源、权限、允许操作和版本检查提交。

整理对话拥有单独的原生记录与来源，不把整段维护指令和技术解释混入主线经历。主线接收已提交的记忆变化，不直接消费后台管理记录。操作成功后才可说明已处理，失败或歧义应如实说明 / 澄清；不因一句普通聊天就跳过提交链。

这不要求整理线变成拥有任意写权限的 Agent。后台自动整理和用户与它对话复用相同的受限维护能力。用户已确认让整理线长期使用同一个私有 Session：维护对话进入该整理 Session，区分于后台任务和主线经历，不为每次对话 / 批次重建 Session，也不随主线按天轮换。具体持久承载与压缩仍须验证，不注册为普通工作区会话；范围见 [12](12-Context内容层级与主线记忆权限.md)。

## 初始记忆与每天第一次对话

初始记忆槽先为空，保留后续带来源的初始化 / 导入位置。现有基本角色说明不等于已经拥有了剧情经历或用户关系。

每日首轮按 [08](08-长期身份与Session分段.md) 组装：

1. L0 当前 `soul.md` 与初始记忆槽（当前无内容则不伪造）。
2. L1 当前 `narrative.md`，承载积累的理解、关系地基与有效取舍，跨天延续。
3. L2 上一段未结束的话题、临时未完成事项与必要约定；不重复携带整份 L1。
4. 有限的工作摘要与必要近期原话，带来源并避免重复抽取；叙事不替代原文。
5. 实际日期、距上次活动的时间和本次相关处境。
6. L4 当前输入，以及 L3 按需检索出的相关记忆。

不复制全部旧日志，不创建独立数值情绪恢复包，不要求主线表演“睡醒 / 今天失忆”。只有基本交接能够可靠恢复才切换活动段；否则沿用旧段并按需要压缩。

## 主动表达的唯一入口

```text
普通工作区的新用户 prompt 被宿主接收
  → 记录接收时间、来源和受限观察材料
  → 可取消的一次性延迟 15 秒
  → 核对任务仍有效、来源、重复、冷却和表达通道
  → 结合 context、情绪线索和活动时长判断是否值得说
  → 不说，或在德谬歌自己的会话生成短回应
```

“输入”按已提交并被宿主接收解释，不监听每次键盘击键，也不等工作 Agent 开始处理或完成回答。15 秒是进入检查的时间，云端生成另有延迟，不承诺第 15 秒必定展示一条话。

观察范围为用户在普通工作区提交的 prompt 与必要时间 / 来源；排除德谬歌主线、整理线、子 Agent、工具输出、自动提醒、压缩内容和恢复回放，避免自触发。来源判定以原生消息归属与请求身份为依据，不能只看文本像不像用户发言。

不会自动读取工作文件、终端输出或整个工作会话历史来扩展情绪检测。确需带入整理 / 主线的观察应有真实来源，在专有日志记录观察范围，保持普通工作会话与德谬歌的控制面分离。只读观察输入不意味着德谬歌获得运行、修改或停止工作 Agent 的能力。

## 情绪线索与工作时长怎样起作用

所有检查仍须来自新 prompt + 15 秒：

- 普通 prompt 可以不回应，不形成“每次提交都说一句”的固定节奏。
- 在该窗口内若措辞表现出挫败、着急或开心，可以让回应更关切、简短或分享喜悦；没有把握时不替用户断言情绪。
- 连续活动较久时可调整表达方式或提出短暂休息的关心；不能在达到某个时长时自行启动新的提醒。
- 连续工作时长按 DSH 活动事件和空闲间隔估算，不把 DSH 常开等同于用户一直工作，也不创建额外的疲劳 / 情绪数值状态。

不在 15 秒前额外起一轮云端情绪分类。需要模型判断的内容放在该窗口的表达评估中；代码先控制何时可以判断 / 发言，模型不能扩大触发范围。

## 避免打扰的执行建议

以下是实现默认建议，未作为已启用功能：

- 15 秒内又有新的普通工作 prompt 时，取消旧候选，按最新输入重新计时；这是一次性事件延迟，不是固定频率轮询发言。
- 同一来源最多形成一个候选；生成中又有新输入时，旧结果提交前再查有效性，迟到结果不得连续冒出。
- 冷却只抑制当前窗口，不在冷却到期后补发。主线或整理对话占用表达通道时，不抢话，也不建立“稍后定时补一句”的另一入口。
- 用户直接对德谬歌或整理线说话时，按正常对话回应，不套用工作区主动表达的 15 秒延迟。
- 主动内容写入德谬歌自己的会话，不作为 follow-up 投回用户的工作 Agent。展示建议不抢焦点、不自动切换工作区；可用轻提示指向专属面板，具体前端通道待验证。
- 宿主重启后丢弃已过时的 15 秒候选，不回放离线期间的主动提醒；真实记忆与后台整理任务按各自协议恢复。

记忆合批、反思、压缩、换段仍可后台进行，完成后不得顺便发言。对用户的主动表达没有固定钟点作息，也不因日记或记忆整理结束而触发。

## DeepSeek 与宿主调用

整理角色使用 DSH 已配置的 DeepSeek 路由，通过 `ctx.llm.prepareCall(...)` / prepared stream 或相应原生 Agent 调用链接入。主对话与整理保持独立上下文和能力，整理不会静默跟随工作 Agent 切到另一个供应商。

精确模型 ID 从宿主有效配置 / 发现结果取得，不在文档中猜型号。宿主没有可用 DeepSeek 配置时报告不可用并保留待整理任务，不自动填写密钥或回退到其他付费服务。沿用宿主已装配的调用中间件，不声称原生必然具备某个每日费用硬上限；暂不增加独立预算管理系统。

## 核对到的原生接口

本轮只读本机 `0.2.0-rc.2` 安装包及 Cordis timer 的公开类型，未修改现用 profile：

| 接口 | 实际职责 | 对本方案的意义 |
|---|---|---|
| `ctx.llm.prepareCall` / `stream` | 绑定模型路由、适配器与调用 | 整理的 DeepSeek 请求使用原生链路 |
| `ctx.timeout` | 一次性延迟，返回取消函数并绑定 Cordis 生命周期 | 适合输入后的 15 秒检查；实现时按宿主注入服务 |
| `ctx.schedule` | 持久提醒，支持 after / at 等，默认投递到原 Session | 不是通用的内部任意回调队列，不能直接用于唤醒工作 Session 的陪伴检查 |
| `session/event` 与 `agent/inbox/spliced` | 接收已提交的 Session 变化与待处理输入 | 候选观察点，需验证新提交、重复请求、输入编辑、首次创建和 steer 的完整覆盖 |

已核对 `dsh-api-session-controller` 的 prompt 接收路径：创建带 `kind: user` 与请求 `rpcId` 的消息，再执行 followup / steer。接收时间与后续 `user/message` 消费时间不同，不能用工作 Agent 完成时间替代触发锚点。

本机安装包包含 experimental schedule bundle，其 patch 注释明确标准 Web 组合不自带这些 schedule 行；不能因为包在磁盘上就假定现用宿主已挂载服务。此次没有自动启用它，也不需要为本方案启用原 Session 提醒投递。

以上是接口 / 源码证据，尚未完成实际输入观察、15 秒取消和专属表达的端到端验收。
