# 动作语汇与首版清单

2026-11-08 更新：本文保留原始建议清单；用户已授权制作到接触类这一档，实际候选、验收和剩余边界以 [25](25-动作系统实施约定.md) 为准。物理解算按后续用户决定保持关闭，以下早期“开启物理验证”不再作为当前模型的验收要求。

日期：2026-11-07。状态：**建议稿，待确认**。前置约束：只走 AI 关键帧（手 K）制作；口型 / TTS 不做；不考虑视频动捕与大显存动作生成模型。混合与过渡机制见 [21](21-动作衔接与AI关键帧方案.md)。

## 为什么先定语汇

手 K 的成本几乎全在"每个动作要逐关节摆姿 + 调时长"。先固定需要哪些动作、每个动作的语义与规格，才能判断：哪些值得精细做、哪些只是常驻背景、哪些可以复用同一段动画。否则会先花时间写混合器，却发现动作清单还没定。

## 本模型的可写通道

PMX 实测：493 骨骼、84 Morph（81 顶点 + 3 材质）、368 刚体、10 根「捩」骨、6 根 IK 骨、42 根手指骨（左右各 5 指 × 3 节 + 指尖）。

| 部位 | 可用骨骼 | 说明 |
|---|---|---|
| 躯干 | `センター`、`腰`、`下半身`、`上半身`、`上半身1`、`上半身2` | 身体朝向与起伏 |
| 头颈 | `首`、`頭`、`両目`、`右目`/`左目` | 眨眼与眼球各自独立 |
| 肩臂 | `肩P`→`肩`、`腕`、`ひじ`、`手首`（可写）；`肩+`/`肩C`/`腕+`/`手捩1-3`（付与输出，禁写） | 自然扭转由 `腕` 旋转经付与链产生，**不要直接写捩骨** |
| 手指 | `親指0-2`、`人指1-3`、`中指1-3`、`薬指1-3`、`小指1-3` + 指尖 | 手 K 成本高，首版建议只做整手与少量拇指 |
| 腿足 | `足ＩＫ`/`つま先ＩＫ`（可写目标）；`足`/`ひざ`/`足首`（IK 链，禁写） | 脚由 IK 目标驱动，链内骨是求解结果 |

不冻结腿部不等于直接写腿骨：小幅摆腿/重心通过**经过校准的 IK 目标**表达。

## 可写通道分类（本模型实测）

按 `rigidBodyType` 与 PMX 付与 / IK 字段分类，493 骨实际是：

| 类别 | 数量 | 代表骨骼 | 规则 |
|---|---|---|---|
| **A 直接姿态骨** | 127 | `センター`、`上半身`/`1`/`2`、`下半身`、`首`、`頭`、`両目`、`肩`、`腕`、`ひじ`、`手首` | 可直接写关键帧 |
| **B IK 目标控制器** | 4 | `右足ＩＫ`、`右つま先ＩＫ`、`左足ＩＫ`、`左つま先ＩＫ` | 只写目标，结果由求解器产生 |
| **C 禁写** | 362 | IK 链 6（`足`/`ひざ`/`足首`）、付与输出 24（`肩+`/`肩C`/`腕+`/`手捩1-3`/`足D` 链/`右目`/`左目`）、物理驱动 332（头发、裙摆、胸、肩领、袖口） | 写了会被覆盖或与求解冲突 |

- 刚体类型分布：静（碰撞代理）36、物理 5、物理+位置对齐 327。**有刚体 ≠ 物理驱动**：躯干/头/四肢上的 type 0 刚体只是碰撞代理，那些骨仍可直接写。
- 眼球：`両目` 可写，`右目`/`左目` 是付与输出（由 `両目` 驱动），禁写。
- 结论：手势 mask 只能用 A 类；涉及脚时用 B 类目标；C 类一律只读。

## 五、表情配对（Morph 已有，只做组合校准）

本模型 84 个 Morph 中可直接配对：`照れ`、`脸红`、`まばたき`、`びっくり`、`驚かす`、`喜び`、`笑い`、`困る`、`やっかい`、`じと目`、`慈愛`、`涙`、`汗`、`汗颜`、`怒り` 等。

| 情绪 | Morph 组合 | 身体配合 |
|---|---|---|
| 害羞 | `照れ` + `脸红` | 低头 + 掩口 / 手放胸前 |
| 惊讶 | `びっくり` 或 `驚かす` | 后仰 + 睁眼 |
| 开心 | `喜び` 或 `笑い` | 轻快点头 + 挥手 |
| 为难 | `困る` + `やっかい` | 歪头 + 摊手 |
| 思索 | `じと目` | 托腮 + 移开视线 |
| 不安 | `心配する` | 双手交叠 + 微低头 |

注意：位移型符号 Morph（`汗` / `！` / `？` / `怒`）需要全量强度才可见，预览默认 1.0。

## 六、首版建议范围（4 个动作 + 常驻层）

- 常驻：`breath`、`gaze`、`blink`
- 动作：`nod`、`tilt`、`wave-small`（`wave` 保留现状作为对照基线）

理由：这几个动作**没有接触约束**（手不碰脸、胸、对侧手，也不进宽袖），只有关节轨迹和时序问题，最适合先验证"动作好不好看 + 过渡平不平顺"。托腮、双手交叠、摸头发这类动作真正的难点是手与脸/手与手/手与衣的间距与穿模，成本远高于点头挥手，放到基本混合稳定之后再排。

`weight-shift` 与 `leg-sway` 不进首版：它们要经过 IK 目标与支撑判断，属于第二组。

## 七、单个动作的规格模板

```text
id: nod
语义: 同意 / 表示在听
触发: 用户说话中、回复开始（高频）
mask: ['首', '頭']
时长: 1.0s（0.15 淡入 / 0.30 保持 / 0.55 返回）
幅度: 首约 +4°、頭约 +9°，沿实际肢段方向而非固定 XYZ
缓动: 五次 smoothstep
可叠加: breath、gaze、blink
冲突: shake、tilt（同骨，新动作淡入、旧动作从当前权重淡出）
循环: 否
退出: 淡出回 base
来源: AI 生成初稿 / 人工校准（记录在案）
```

## 八、验证顺序与待确认

首轮只验证四件事（不扩动作、不做状态机）：

1. 单段 `wave-small` 是否自然：肩肘腕轨迹、手是否穿宽袖、上臂是否压进外套。
2. `wave-small` 与 `nod` 能否同时播放且互不覆盖。
3. 任意时刻停止 / 切换到另一个动作是否平顺，结束后是否回 base 且无残留偏移。
4. 开启物理后是否仍然稳定（帧率与骨骼有限性）。

待确认：

1. **制作工具**：先用 MPL（GPL-3.0）离线生成一版 `wave-small` 候选、再用 Reze Studio（GPL-3.0，已核验）本地修正，还是直接手工 K 帧？两者都不进运行时依赖。
2. **动作来源记录**：每个动作是"AI 生成初稿 + 人工校准"还是纯手工，需要在文件里留字段（便于以后判断质量与复现）。
3. **手指细节**是否进首版（当前建议不进）。
4. **`汗` 这类符号 Morph** 是否作为常态表达，还是只在调试面板保留。
5. 若 `wave-small` 验证通过，第二批优先级：`shake`、`lean-in`、`weight-shift`/`leg-sway`（IK 目标）、最后才是接触类（托腮 / 双手交叠 / 摸头发）。
