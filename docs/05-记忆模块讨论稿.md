## 三种隔离分别处理

| 边界 | 要解决的问题 | 当前证据 |
|---|---|---|
| 普通 DSH 工作区与专有运行服务 | 普通会话列表、搜索和控制面不持有专有 Session | 已实现独立原生 Context，并验收列表 / 搜索与宿主服务归属 |
| 主模型与底层写入 / 状态 / 调度 / 授权 | 主模型不能通过工具调用或文本输出直接更改机制 | 当前原型没有这些模块；工具为空不能充当这些模块的隔离验收 |

独立 Context 不是模型职责边界，也不是操作系统沙箱。桥接宿主凭据是模型调用接入问题，不能替代上述隔离。

## 权责与可见内容

| 角色 | 输入 / 可见内容 | 可输出 / 可持有能力 |
|---|---|---|
| 主对话模型 | 经授权的近期对话、自我叙事、自然语言处境与状态、低密度记忆预览；按需提供受控只读引用 | 自然表达，不承担常规记忆维护决策，不持有日志写入、记忆维护、状态设定、调度和授权能力 |
| 记忆写入管线 | 真实通道提供的原始事件、允许处理的历史与独立抽取结果 | 独立云端整理调用提出结构化候选，代码执行来源、schema、准入、冲突和权限检查，专属提交者落日志 |
| 工作输入门控 | 普通工作区新 prompt 的接收事实、时间及可重建活动信息 | 只在输入后 15 秒检查主动表达；不建立独立情绪 / 关系数值状态，不让模型改变触发机制 |
| 整合任务 | 调度器选定并授权的时间范围和资料 | 独立模型调用形成摘要 / 叙事 / 生命周期候选，仍由受限提交链校验并记录；不授予后台模型通用写权限 |
| 上下文组装器 | 已提交投影、授权结果、当前话题、时间与预算 | 产生供原生上下文机制消费的视图，不交给主模型挑选哪些内部规则生效 |

主模型与后台模型可以采用相同供应商，甚至相同型号；仍需分开调用上下文和能力集合。独立调用本身不建立可信性，后台模型输出同样需校验。当前以云端整理为讨论方向，不安装本地推理栈；调用频率、片段大小和具体模型另议。

主模型可以看到“你明天有面试”和“这件事仍未结束”，不必看到数据库行、状态分值、检索评分、调度阈值或授权管理记录。原文允许的 `memory/<id>` 预览与只读引用不等于开放任意文件读取。数值不直接给模型，并不意味着靠隐藏数值获得权限控制；真正边界在能力与提交接口。

## 信息流与独立因果链

```text
真实通道事件 / 时钟
  → 原生 Session 事实日志
  → 独立抽取与规则闸门 → 记忆 / 生命周期决定提交
  → Context 处境与工作输入门控
  → 授权过滤与记忆选择
  → 面向表达的上下文视图 → 主模型 → 表达结果

真实经历与当前叙事 → 整理线主动取舍 → 校验与受限提交 → 后续记忆 / 叙事视图
```

记忆与状态的处理不以“主模型已成功回答”为唯一触发条件。主模型超时、不可用或更换型号，不能使已收到的经历丢失，也不能让时间门控、已有投影读取和恢复依赖它。依赖模型的抽取 / 整合任务可延迟，延迟与待处理水位应明确保留。

主模型说“我已经忘记了”不会执行遗忘；说“信任值现在为满”不会修改状态；说“以后每分钟唤醒我”不会创建调度。主动遗忘由整理线处理，不等待主线提出或审批；普通台词不成为管理命令。接受决定与结果可追溯，但主线不需要宣告维护过程。

由对话内容间接影响记忆与状态是预期功能；隔离不意味着世界不能影响她。要防止的是：将生成文本当管理命令、来源证明或策略覆盖，以及让一次模型调用持有底层管理能力。

## 独立云端整理调用

整理调用由 DSH 插件内部任务队列驱动，使用宿主 LLM 接口，不增加常驻进程，也不创建普通工作区聊天。其输入为程序划定的日志片段、可信的来源与时间、相关已接受记忆及整理规则；上下文不沿用主对话的完整历史，不持有状态、调度、权限或日志管理工具。

输出采用严格 schema，包含候选记忆、证据引用、冲突 / 取代建议及可选的保留 / 放下提议。程序校验操作种类、目标范围、证据是否存在、来源与授权，再按操作 ID 和基准版本提交；过期结果需要重新核对，不能覆盖较新的记忆。schema 和引用检查不能证明语义绝对正确，仍需保留依据、待确认状态、冲突与可回溯版本。

主对话的表达与提议可以成为整理材料，但不会自动取得管理效力。整理任务不能凭对话文字更改人格规则、状态系数、权限或时机门控。夜间叙事整合可沿用该任务设施，但有不同的触发条件和允许操作范围。

先用有界增量片段整理，按结算轮次或片段边界触发；积压时合批，不要求每条消息额外调用一次 API。整理异步进行，下一轮可读取截至明确日志水位的投影，并保留尚未整理的近期原文。失败保留待处理水位，重试不重复提交；回复不能假称尚未完成的整理已经生效。

## Session 事实与模型上下文必须分开

Session 是事实源，模型上下文是其中经解释、筛选与授权后的视图。时钟、记忆准入、来源与版本、生命周期决定、状态依据、调度结果和后台整合过程不应因持久化需要被全部注入主对话。

下一步先验证内部记录的承载方式：持久化、重建、主模型不可见、并能审计来源。此前实验只证明原生消息槽位的注入 / 替换与回放，尚未证明外部插件可安全持久化任意非模型可见事件。不能仅扩展 TypeScript 类型就假定持久化兼容，也不借用内部实验 API。

具体采用同一 Session 的受支持非模型可见记录，还是私有运行域中的内部原生 Session，需通过小型实验比较；后一种还需定义跨 Session 来源、提交顺序与恢复水位。这里只列候选，不预先定案。不得为了落日志而把全量内部账本伪装成用户对话、写入人格 system prompt，或强行塞进主模型的 surface。

## 记忆模块保留的产品语义

保留原文的事实 / 偏好 / 经历 / 承诺 / open-loop、关系地基、自我叙事与分层资源，而非只有“用户资料”。常驻的是少量叙事与关系地基；近期经历与未完成事项参与选择；冷记忆可追溯并按需读取。低密度注入允许零条，不要求每轮提到旧事。

保护、强化、冻结、降权、放下与被新事实取代，要保留来源、理由和版本。真实相处叙事包含保留与放下的取舍，soul 承担较稳定的人物底色和表达材料，两者分开但可关联。soul 不只是形容词命令表，也不只是一份事件摘要；维护版本仍需可追溯，不能绕过日志。

降低主动提及、从当前上下文撤回、禁止访问和物理删除语义不同，不能统一成一个删除开关。授权禁止的内容必须在进入模型前过滤；日常记忆的淡化与归档不必伪装成不存在原记录。检索和上下文选择均受同一边界约束。

后台整合与按日维护可以由宿主内事件和时间驱动；DSH 未运行期间不能补写不存在的经历。面向用户的主动表达只由工作 prompt 后 15 秒窗口触发，不做固定时刻发言或独立睡眠状态。原生上下文压缩参数继续按实测调整。

## 下一步先验证什么

完整流程、数据分类与一个贯穿例子见下文「端到端方案」。

先证明隔离契约，再扩大记忆功能：

1. 主模型请求只包含授权的表达视图，不带内部控制记录；它不持有底层管理工具。
2. 生成控制指令、伪造结构化字段或请求越权目标，不会造成记忆提交、状态赋值、调度或权限变更。
3. 独立抽取 / 整合候选经过相同的来源与准入检查，不能凭“后台模型”身份直接写入。
4. 记忆与状态决定能持久化并按已接受决定重建，不通过重跑模型生成另一版解释。
5. 主对话失败不丢失输入经历；时钟 / 门控与待处理任务有独立运行和恢复路径。
6. 允许的保留 / 放下提议可以通过独立裁决生效，并与她后续的叙述对得上。

以上为后续实现的验收要求，不是当前原型已经通过的测试。本次仅整理设计文档，没有添加记忆、状态或调度实现。

## 端到端方案

### 数据职责

| 内容 | 含义与归属 |
|---|---|
| 原始经历 | 原生 Session 中收到、说出或由可信通道观察到的事件，保留原文、身份、时间。记录用户陈述不等于验证了陈述中的客观事实 |
| 记忆单元 | 事实 / 偏好 / 共同经历 / 承诺 / 未完成事项，含主体、时间、证据、依据类型、有效状态和版本 |
| 关系地基 | 长期影响相处方式的称呼、约定和边界，可从记忆与接受决定推导，不能仅因久未提及自动消失 |
| 积累的自我与关系叙事 | 对经历、思考与取舍形成的跨日理解；可读投影为 L1 `narrative.md`，与 L0 `soul.md` 分开 |
| 查询投影 | 按主体、时间、词项、状态与来源检索的结构，可用 SQLite 保存；向量索引是后续可加的查询设施 |
| 运行记录 | 整理任务的来源范围、已提交版本、去重操作 ID、处理位置、策略版本，供恢复和审计；不作为主对话材料全量注入 |

原生日志及其已提交决定为唯一事实源。SQLite、向量、叙事文件与内存状态都可以删除后重建。重建使用已接受结果，不重新向模型请求另一份解释。

### 收到消息之后

1. 由宿主接收并记录事件，actor、时间和消息 ID 来自通道，不由模型提供。即使主对话请求随后失败，收到的经历也应保留。
2. 主对话从当前已接受记忆及近期原文组装上下文，按时机与权限允许后运行。
3. 结算的对话片段进入增量整理队列。输入包括明确的起止事件、相关旧记忆、允许的操作和基准版本；不把整个聊天库反复发送。
4. 独立云端调用提取候选，提出合并、冲突、取代、未完成事项变化及取舍建议。
5. 唯一提交者做 schema、来源范围、版本、允许动作及授权检查。证据不足进入待确认，不因 JSON 格式正确就作为已核实事实。
6. 先将接受决定与处理位置写入原生日志，再更新查询投影。操作 ID 防重复；落后于当前版本的结果重新核对，不能覆盖新决定。
7. 后续对话看到新版本；若整理尚未完成，则仍通过近期原文知道刚发生的事。当前回复不能宣称后台尚未完成的维护已成功。

同一记忆域的提交串行化。调用可以失败或延后，不应先移动处理位置再丢掉未提交结果。持久化失败时停止接受后续维护提交并显式报告，不能静默只更新缓存。

### 两类整理任务

增量整理处理最近片段中的事实、经历、承诺和冲突。低频整合处理已经接受的较长时间范围，生成叙事、关系变化和生命周期候选。两者使用同一云端调用设施，但拥有不同输入范围、频率、预算与允许操作；不必绑定不同型号。

后续用户已确认整理线长期保留同一个私有原生 Session；两类任务与用户维护对话在该 Session 中区分记录和串行执行，不按批次重建或随主线每日换段。工作上下文仍有界压缩。L3 本次召回由检索 / 组装代码从已提交记忆产生，不要求整理线每轮另写一段回忆；主线可主动发起只读回想、补查和原话展开，无需整理线逐次批准。整理线记忆域维护权限和主线叙事理解提交权也已确认，具体边界见 [12](12-Context内容层级与主线记忆权限.md)。

任务由宿主内时钟和队列驱动。说话时机与整理时机分开，整理成功不自动获得主动发言权。DSH 没运行的时段只可记录缺席事实，不补写不存在的感知或活动。

### 每轮想起什么

先由代码确定可读取的范围，再用当前话题、最近几轮、时间及相关未完成事项构造查询；召回可包含关键词 / 实体、时间与状态、多路检索和相关性排序。向量是否进入首版根据质量验证决定，不用纯相似度作为唯一依据。

组装内容分为少量常驻叙事 / 关系地基、当前自然语言处境、选中的近期或历史记忆、近期原文。历史记忆低密度注入，允许没有命中；可查证的只读资源供按需展开。每项有独立预算，避免把全量库注入或重复保留所有旧快照。

原生 Session / surface / context 承担模型可见历史与替换，LiveSeed 决定内容选择。压缩在实际窗口需要时使用，不把压缩摘要当长期记忆本体。内部控制记录的持久承载与主模型不可见仍是实现前必须验证的接口问题。

### 保留、放下和叙述

整理线可根据真实经历与当前叙事自主选择保留、淡化或归档，不要求主线先表达维护意愿。用户提出“请记住”等明确要求仍可成为整理材料，实际动作经独立提交链生效。保护、降低主动提及、冻结、取代和放下具有不同效果与理由，不统一为删除。

她可以保留原文而不再主动提起；这与无权读取、用户撤回以及从持久层物理删除不同。禁止读取必须在模型输入前落实。后续日记只能把已接受的取舍写成完成事实，不能用一句生成的日记倒推底层操作已经发生。

### 贯穿例子

用户说“周五面试，有点紧张”：先留原文，增量整理可提出一个带来源和日期依据的未完成事项，不把“紧张”永久化为人格特征。下一轮即使整理未完成，也能从近期原文接话。

周五是否主动问候由时钟、权限和说话门控决定；记忆模块只提供相关事项。用户后来说明“延期到下周”，产生有来源的新版本，旧日期保留为历史，不继续作为当前提醒依据。

整理线可将一起准备面试的片段保留为共同经历，同时淡化已经结束的临时安排，不需要主线先说“我想记住”。视觉模块目前搁置，后续表现接口仍不能改变记忆、状态或事项日期。
