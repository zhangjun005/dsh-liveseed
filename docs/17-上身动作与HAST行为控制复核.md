## 用户补充的动作范围

日常表现以上身为主：头部、肩膀、手臂、手腕和躯干。腿部较少进行大距离移动，但仍需保留小幅摆动和随重心变化产生的动作。因此不将下半身整体冻结，也不把走路、跑动和跨场景寻路作为首版基础依赖。

建议固定角色在网页舞台中的锚点，允许髋部在局部小范围移动、轻微屈膝和重心转移。站姿时支撑脚维护接触，摆动脚需要协调支撑与收回；“原地”不等于每帧将髋部或腿骨清零。裙摆 / 发丝的被动物理由 MMD 执行器处理，不能代替主动腿部动作。

此前将 HAST 仅描述成参数设计参考不够完整。它有可借鉴、适配的行为控制链；这些机制分布于多个模块，并非一个可直接导入所有角色格式的独立 FSM 包。

| 层 | 本地源码 | 实际作用与接入判断 |
|---|---|---|
| 基础行为 | `motion/base_policy.mjs` | 管理 intent、speaking、listening、短时交流；局部动作执行期间锁住基础原型切换，延后处理新的基础意图。适合改为 DSH 事件驱动的表现状态控制 |
| 待机 / 活动选择 | `web/v14_base.mjs` | 根据当前姿态及行为条件，用学习权重选择 chat / idle / activity，处理循环与切换淡入。其 53 骨骼顺序、权重和素材注册表绑定，不是状态名称即可复用的独立逻辑 |
| 局部轨道 | `motion/beat_layers.mjs` | 按骨骼 mask 混合，支持幅度、速度、延迟、保持、循环；冲突轨道淡出，按角距调节过渡时间，避免在上一帧结果上累加旋转。优先复用其控制机制 |
| 动作候选选择 | `web/v13_policy.mjs`、`v14_policy.mjs`、`v15_policy.mjs`、`v15_wave.mjs` | 根据有限意图和姿态历史选择已存在的动作片段 / 周期，依赖配套权重及动作码。不是任意文本生成动作，也不能移植后省掉动作素材 |
| 脚部接触 | `motion/v9/contact.mjs` | 包含支撑、卸载、摆动请求、落回及重接触处理；腿部小摆动仍可受益，需要适配目标体型与接触参数 |
| 可行性求解 | `motion/v9/controller.mjs`、`projector.mjs`、`post_solve.mjs` | 处理关节范围、支撑、手部目标、阻尼与失败保留；属于独立工程任务，不能在当前 PMX 上直接启用 |
| 求解 / 显示时钟 | `motion/v9/clock.mjs` | 示例以 20Hz 固定步长求解，显示时插值并验证。可参考双频率机制，20Hz 本身不是本产品已测得的合适数值 |

`web/v15_controls.mjs` 展示的 idle / chat / activity / command / release / brief / conversation 是界面状态名称表，实际转换、局部覆盖和对话交互在上述模块共同实现。

## 建议采用的组合

保留 AIRI 所用的 three-mmd 作为 PMX 加载、材质、动画与物理执行基础；在其上建立参考 HAST 的表现状态控制与局部轨道。Reze Rig 继续只是可选的离线动作素材入口，不能代替运行时状态控制。

```text
已校验的主线事件 / 实际播放状态
    → 表现状态控制（待机、聆听、回应、暂停）
    → 基础姿态 + 局部手势轨道 + 下身支撑策略
    → PMX 骨架适配与通道仲裁
    → 唯一的 MMD 更新链（动画 / IK / 继承变换 / 物理）
    → DSH 根级常驻舞台
```

基础行为与手势生命周期分别管理，避免把所有组合展开成互斥状态。例如“聆听 + 小幅点头”可同时成立；手势按进入、执行、收回、中断淡出管理，通常只占用其声明的骨骼。仅在必要时锁定基础动作切换，呼吸、眼睛和不冲突通道可继续。

上身手势只占用需要的肩 / 臂 / 头 / 躯干轨道，保留下身待机；需要髋部参与的前倾和重心转移，应声明对下身支撑的要求。下身局部摆动声明摆动侧与支撑侧，退出时平滑落回。若输入素材包含全身轨道，需要在素材阶段整理影响范围，不能随意剪掉腿部后假定原动作仍然平衡。

这些只是运行中的表现状态，不存储“好感 / 悲伤值”，不写回 soul / narrative。真实音频播放事件才驱动说话和口型状态；没有音频时可以有文字回应手势，但不能将生成 token 当成正在发声。

## 不能原样搬入的部分

1. **VRM 标准骨架。** `PoseController` 直接依赖 `vrm.humanoid.getNormalizedBoneNode()` 等接口；`feasibleRig` 假定 hips 为根、父级优先的树，跳过的附加骨骼需为标准静止姿态。当前 PMX 含额外控制骨、继承与 IK，不能只换骨名或将 493 骨骼数组塞入 53 骨骼权重。
2. **归一化空间与标定。** 需要映射语义骨骼到 PMX 的实际控制链，处理参考姿态、局部轴、比例与单位。已静态确认模型有下半身、左足 / 左ひざ / 左足首及足 IK 等骨骼，但控制关系仍需实际执行器验证。骨骼映射本身不等于完成重定向。
3. **多个求解器争写。** 首版优先由 MMD 原生更新链处理已有 IK / 继承变换和物理。若引入 HAST 全身求解器，应明确哪些骨骼由它输出、哪些 IK 被启用及执行顺序；不能在 MMD 算完后每帧再覆盖全身，或对同一约束重复求解。脚部接触可先实现目标 / 策略适配，再评估是否引入完整求解器。
4. **原产品的主动聊天。** `web/v15_dialogue.mjs` 在进入 chat 基底等条件下会主动请求聊天，并设置内部冷却；`v13_command.mjs` 有独立 API、上下文和队列。只移植表现机制，语言调用继续使用 DSH 主线；动作状态、循环结束和定时冷却不得绕过已确认的普通工作 prompt 后 15 秒触发窗口。
5. **页面与固定资源地址。** 原有 DOM、气泡、调试图表和 `/v15-data/` 等路径依赖自身服务。需要适配成现有原生 Remote 与受控资产加载，不嵌入整页或常驻另一套 Qwen 服务。

学习策略的选择可以暂由规则和已验收片段替代；这仍保留行为状态、轨道混合、支撑和过渡机制，但不应宣称复现了原有学习运动底座。若后续需要原学习效果，另验证其权重、动作码、数据许可与重定向结果。

## 代码复用的实际许可边界

当前 HAST 原创代码采用项目自定义的非商业学习研究许可，允许该范围内的使用、复制、修改及保留声明的免费再分发；商业产品 / 服务等另需书面授权。它不是 AIRI 的 MIT 许可，不能将复制出的模块改标为 MIT。参考其机制自行实现与直接复制 / 改造源码需要在来源记录中区分，前者也不等于允许照搬其权重或素材。

当前先确定机制与适配边界，尚未复制 HAST 代码或权重，也没有扩大现有角色素材的使用范围。

## 实际接入的优先顺序

1. 用当前 PMX 验证待机、上身手势 mask、停止和收回，确保切换工作区仍只有一个舞台。
2. 加入髋部小范围位移和双脚支撑，验证轻微重心转移时脚不滑、膝盖不反折。
3. 验证单侧小幅摆腿、重心准备与落回，检查裙摆效果和视线覆盖问题；不以大距离行走作为前置条件。
4. 根据上述实际质量及性能，再决定引入 HAST 完整求解器或学习策略的范围。

本轮仅更新设计文档，未运行渲染、性能或动作质量验收。
