# PMX 常驻舞台首版与验收

日期：2026-11-07。实现入口：[角色模块](../src/client/character/README.md)。设计依据：[06](06-网页角色展示与驱动方案.md)、[15](15-本地角色模型检查与MMD适配.md)、[16](16-AIRI接入与动作来源调研.md)、[17](17-上身动作与HAST行为控制复核.md)、[18](18-完整PMX骨架与表情适配方案.md)。

## 本次实现

- DSH 根级 `shell.overlay` 挂载一个透明 Canvas，切换普通工作区 / 聊天 / 整理 Session 不重新创建渲染器。拖拽把手接收指针，画布默认穿透。
- 原生 Modal 设置新增“角色”分类：本地模型、显示、大小 / 位置恢复、动作与全部 Morph 预览、可选头发 / 服装物理。界面状态保存在当前浏览器，不建立持久情绪或关系数值。
- 选用 `@takahirox/three-mmd` `0.1.4`、Three `0.186.1`、对应类型 `0.186.0`。原生保留模型的 493 骨骼与 84 Morph；不删骨、不重蒙皮、不转换为 VRM。
- 单一 MMD 更新链处理 IK、继承与物理；程序身体输入、双眼控制及 Morph 在自有 mixer 采样后、原生求值前写入。没有使用 AIRI 的求解后头部覆写方式。
- 提供轻微呼吸 / 眨眼 / 视线和点头、挥手、身体侧倾、原地重心变化、单侧轻摆腿。腿部预览使用足 IK 输入，D 骨等继承骨交给执行器处理。
- 角色资源走宿主原生 Connection Fetch 的认证 / Host / Origin 边界；JSON 清单走已有 Typert Remote。没有恢复私有 JSON 轮询 API。清单没有绝对文件系统路径，资源只允许已登记 PMX 与图片，不提供任意路径读取或规则文档下载。
- 默认寻找插件项目目录中的 `CharacterModel/`；宿主配置可用绝对 `characterDir` 指向自有模型目录。分发包不带角色，目录缺失时其余对话功能仍可用。
- 可选 Bullet 来自 MMD 包内固定 WASM，首次启用时通过固定的受认证资源入口加载，默认关闭。关闭舞台 / 后台页面暂停逐帧更新，恢复限制时间步；插件 / 页面卸载时释放可释放的场景与物理资源。
- 构建输出保留 Three / MMD / parser 许可；Bullet 的源码、编译器与运行库许可仍随依赖包保留。参考 AIRI / HAST 的设计不等于复制其全部代码或权重。

## 实际验证

真实本地 PMX 验收使用独立 DSH_HOME、临时端口和合成模型服务；没有请求真实聊天 API，也没有修改现用 profile。验证包括：

1. 从真实宿主认证资源路由加载模型与贴图，完成浏览器渲染，确认 493 骨骼、84 Morph（含 3 个材质 Morph）。
2. 逐一选择 84 个 Morph，等待实际更新帧并检查应用权重；“照れ”导致真实材质状态变化，清除后材质回到基础状态。
3. 基础动作、停止与重置；开启物理后短时运行、确认骨骼数据有限，再关闭物理。
4. 显示开关暂停 / 恢复更新；切到普通工作区或整理 Session，Canvas 对象身份保持一致。
5. 未认证资源请求被原生边界拒绝；资源单元测试检查不透明 ID、路径穿越 / 未登记文件拒绝、规则文件不发布、junction 不跟随、缺失目录可用。
6. 姿态回归检查重复动作与停止后归位、不积累旋转、派生骨不被预览驱动直接修改。该测试发现并修正了恒定 mixer 轨道缓存造成的程序偏移累加。
7. 人工查看本地截图后，移除重复环境光并降低方向光，改善白色材质过曝；启用原有材质描边。尚未进行与原生 MMD 的逐像素外观比较。

真实模型的截图、原始浏览器日志与全部产物保存在被忽略的 `.local/character-acceptance-*`，不提交、不打包。公共常规 Web 验收强制使用空角色目录，继续验证合成对话、记忆与原生输入框。

命令、版本与私有产物位置见 [验收摘要](validation/liveseed-character-2026-11-07.json)。

## 2026-11-07 显示、动作与帧率修正

- 缩放改为 25%–600%，提供“上半身构图”。拖拽把手在模型上方，允许身体延伸到页面外，位置可保存；仅保证把手仍可操作。相机裁取屏幕可见区域，避免放大后渲染大量屏幕外像素。
- 先前默认待机的压臂姿态使手部藏入宽袖附近；挥手还假定肘关节沿固定 X 轴弯曲。这些是程序姿态问题，当前尚无 FBX 动作转换。现按实际肢段方向计算上臂 / 前臂目标，在躯干坐标中校准并平滑过渡；已人工检查待机双手和抬手问候截图。
- 删除约 30fps 的旧限帧方式，使用约 60fps 的时间截止点调度，避免小幅超时被舍入成整帧跳过。诊断扫描降为按变化及低频执行。
- 开启完整物理后的主线程瓶颈还包括 332 个动态骨骼回写时反复遍历全树；仅将 Bullet 移入 Worker 不足以解决。当前使用网页 Worker 加有限的整树刷新合并，保留所有刚体 / 约束和逐骨回写，并自动与原算法做数值对比。不修改原始 PMX、不修改依赖安装目录。
- 同机隔离测试中，旧无物理约 28.8fps；修正后无物理约 57–60fps。旧同步物理约 35fps / 主线程更新 26ms；优化后物理开启约 60fps / 更新 5.4ms。数值是本机短时观测，不是所有硬件或长时间运行保证；当前测试使用 RTX 4060 Laptop 的 ANGLE WebGL2 后端。

## 2026-11-07 表情预览与符号 Morph 修正

- 模型里"汗 / 汗颜 / ！ / ？ / 怒 / 111"等是**位移型顶点 Morph**：只移动 4 个顶点的贴片，把它从头后的隐藏位置推到头侧前方。按半程（0.5）预览时贴片仍藏在头发里，看起来像没有渲染。
- 表情预览选中时的默认强度改为 **1.0**；滑杆仍可下调。`汗` 在 1.0 时头饰旁可见蓝色汗滴；`汗颜` 的目标位置被前发遮挡，属模型自身的遮挡关系，不是渲染遗漏。
- 验收补上像素级断言：选中代表 Morph 后，画面顶部带必须出现待机动画不会产生的饱和蓝色像素（本次实测 54）；此前只校验写入的权重，因此 0.5 档位从未被真正看到过。
- 复核同时确认 84 Morph = 81 顶点 + 3 材质（PMX 2.0 的 type 8 为材质 Morph，"照れ"即此类，材质变化已验证）；手势之间的过渡与状态机方案另见 [21](21-动作衔接与AI关键帧方案.md)。

## 本地使用

先 `pnpm build`，重启开发 DSH 后刷新网页。角色会随页面出现，在德谬歌设置 → 角色中操作；现有普通工作区无需加入模型路径。

```powershell
$env:LIVESEED_DSH_ROOT = 'D:\nodejs\npm-global\node_modules\@deepseek-ai\dsh'
pnpm test:character
```

该命令使用项目 `CharacterModel/`，可用 `LIVESEED_CHARACTER_DIR` 指定另一个已获授权的本地测试目录。测试会自动关闭隔离宿主；不把临时验收实例当成日常启动器。
