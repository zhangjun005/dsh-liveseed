AIRI 的 MMD 路径是本地已存在的独立执行分支，不应把它与 AIRI 的 VRM / Live2D 分支混为一谈。具体入口：

- `packages/stage-ui/src/components/scenes/Stage.vue`：选择 `mmd` 时挂载 MMDScene。
- `packages/stage-ui-mmd/src/composables/mmd/loader.ts`：使用 `@moeru/three-mmd` 的 MMDLoader / VMDLoader。
- `packages/stage-ui-mmd/src/constants/morphs.ts`：口型、眨眼和表情候选名。
- `packages/stage-ui-mmd/src/composables/mmd/animation-manager.ts`：动画、IK、继承变换与 Ammo 物理的生命周期。

模型中的五个日语元音口型、眨眼、左右眨眼以及微笑、愤怒、悲伤、惊讶、困扰、认真，均能匹配 AIRI 的 **14 个默认 Morph 槽位**；`両目`、`左目`、`右目`、`頭`、`首` 五个视线 / 头部骨骼也都存在。这是名称和结构匹配，尚未验证实际表情观感。

## 对 LiveSeed 方案的影响

这份实际素材适合优先走 **Three.js + MMD 执行器**。参考 AIRI 的底层加载、材质、动画与物理处理方式，按最新要求挂载到 DSH 根级常驻浮层，不要求嵌入 AIRI 的 Vue / Pinia 整套应用。上层行为控制可适配 HAST 机制，见 [17](17-上身动作与HAST行为控制复核.md)。

不必为了套用 VRM 执行器先转换模型。若以后确有 HAST-SEC / VRM 动作重定向需求，再单独验证人形骨骼映射、表情重映射、材质 / 附加 UV、物理与辅助骨骼迁移；仅导出为 GLB 不会自动生成 VRM humanoid 语义。转换结果同样仅本地保留。

下一步运行验证应先检查 PMX 与完整贴图加载、材质与基础骨骼 / 表情，再分级开启头发 / 裙摆物理并测量性能，最后接入动作资源和主线意图调度。368 个刚体和 572 个关节意味着必须实测物理成本，不能由 PMX 文件体积推定性能。

主线只产生受限动作意图，记忆整理不直接触发角色播放；权限、原生日志事实与模型表现的边界继续遵循 [06](06-网页角色展示与驱动方案.md)、[11](11-叙事续接式Context与表现协议.md)。本轮没有安装渲染依赖、运行他项目的模型导入脚本或分发任何模型资产。
