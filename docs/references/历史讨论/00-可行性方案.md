## 0 一句话结论

**能做，但要接受它的定位：一个「像德谬歌」的记忆体/陪聊，不是通用助手。**
三条硬约束决定形态：8 GB 显存（实际可用 ~6 GB）、16 GB 内存（实测仅剩 2.4 GB 可用）、C 盘只剩 4.8 GB。
主路线：**Qwen3-1.7B（bf16 LoRA，零第三方黑箱）→ 上线可换 4B-Instruct-2507（QLoRA）**，外面套**四层记忆系统**（工作记忆 / 情景记忆 / 世界知识 RAG / 人格-成长状态），记忆检索复用项目已有的 bge-small-zh。

**方法论上和 bge 那条线保持一致：先做「不训练」的基线（prompt + RAG + 记忆），用冻结的评测证明「LoRA 确实带来了增量」，再上微调。** 不做没有对照的实验。

## 2 为什么「德谬歌」这个选题特别合适：设定 ↔ 架构同构

语料里德谬歌的设定（出处见各条 record）：

| 设定 | 出处 | 对应本方案的哪一层 |
|---|---|---|
| 「最初的智种」「不应存在的第十三位泰坦」「翁法罗斯之心」 | `data/config/speaker-alias.v3.json`、`l3-昔涟`（#23117–#23119、#24200） | 人格底板（system prompt + LoRA） |
| 权杖 δ-me13 的**原始演算目标**，课题叫「生命的**第一因**」，被赞达尔用星核「亲手扼杀」、从演算中剔除 | 3.6「诸神啊，奏响创世的凯歌」#? / 3.7「魔女的孤诣课题」| 「内核被删掉的 AI」——它的记忆本来就不完整，**遗忘是设定的一部分** |
| 形态演化：**德谬歌(种子) → (幼芽) → (花蕾) → (花) → 心 → 迷迷 → 昔涟** | `speaker-alias.v3.json` stage、`l3-昔涟`（记忆形态 160 条） | **成长状态机**：记忆越多，阶段越高，语气也随之变化 |
| 本质是**倾听者**：三千万世「记忆」的听众 | 3.7 大墓段 #23105–#23107 | 记忆系统就是它的本体：**先听，再记，再说** |
| 断句体（「memi~」「你…温暖。温暖，喜欢。」），全篇第一句与最后一句是同一种语法状态 | `l3-昔涟` §135 | 风格指标的地板/天花板：均长 6.5 字、0.17 个逗号/句 |
| 称呼「桃子」（3.7 记忆形态段 39 次，后反向用来叫「往昔的涟漪」） | `l3-昔涟` §87 | 口癖/称谓评测项 |
| 水晶花寓言被改写两次；「收梢即起始」 | 3.7 #23888–#23913、#25226–#25231 | **自我叙事可被重写**：反思模块每次重写「我是谁」的历史版本要留档 |

**现成语料规模（实测）**：按 `speaker=昔涟` 或 `form∈{迷迷, 记忆形态, 往昔的涟漪}` 粗计 **2,645 条台词 / 56,042 字**；句长 P50 = 19 字、P90 = 38 字（短句为主，和断句体设定一致）；把「前 1–3 条对白」当上下文、人格台词当回答，可**免费**拼出 **2,320 条多轮样本**（不需要任何 API 调用）。

## 3 模型选型：8 GB 显存下的算术

| 模型 | 权重(bf16) | 权重(4bit) | 训练可行性（本机） | 推理 Q4（约） | 结论 |
|---|---|---|---|---|---|
| Qwen3-0.6B | 1.2 GB | 0.4 GB | 很轻松（甚至可全量 SFT 小试） | ~0.5 GB | 只当「种子期」彩蛋，不做主对话 |
| **Qwen3-1.7B** | 3.4 GB | 1.1 GB | ✅ bf16 LoRA + 梯度检查点 + seq 1024 可跑（约 5.5–6 GB） | ~1.1 GB | **训练首选**：不依赖 bitsandbytes，风险最低 |
| Qwen3-4B-Instruct-2507 | 8.0 GB | 2.3 GB | ⚠️ **bf16 放不下**，必须 4-bit QLoRA（需 bitsandbytes 在 Windows 可用） | ~2.4 GB | **上线首选**：纯推理很舒服；训练是「升级项」 |
| （不建议）7B+ | — | 4.5 GB | ❌ 8 GB 显存训不动，推理也挤 | ~4.5 GB | 不做 |

**两个必须注意的点**：
1. Qwen3 是混合思考模型 → 人格对话必须**关思考**（`enable_thinking=False` 或 `/no_think`），否则会把「内心独白」写进气泡；2507 系列本身就是非思考，天然干净。
2. 4060 Laptop 的 8 GB 是**共享的**（桌面/浏览器也吃），训练前确认 `nvidia-smi` 空闲 ≥5.5 GB。

## 4 训练方案：三档递进，先证明再训练

| 档 | 做什么 | 成本 | 产出 | 何时进入下一档 |
|---|---|---|---|---|
| **T0 不训练** | system prompt（人格设定 + 断句体规则 + 口癖） + 8–12 条 few-shot + 记忆检索桩 | 半天 | 能聊、但「像」的程度未知 | T0 在风格/记忆评测上的分数就是基线 |
| **T1 LoRA SFT** | 三类样本训练小模型学「说话」和「记住」 | 1 天 | merged 模型 + GGUF | 只有 T1 比 T0 有可测增量才保留 |
| **T2（可选）记忆行为微调** | 训练「主动引用记忆 / 承认遗忘 / 阶段化语气」的固定行为 | 0.5 天 | 行为更稳 | 视 P3 评测决定 |

### 4.1 数据构造（三类样本，全部本机生成，不调 API）

| 类型 | 构造方法 | 规模（估） | 目的 |
|---|---|---|---|
| **A 多轮语境** | 语料里连续对白：前 1–3 条 → 目标人格台词；附 `(version, task, step)` 当场景提示 | 2,320 | 学「接话」而不是背台词 |
| **B 风格单轮** | 人格台词 + 最小情境化指令（如「（你把书翻到某页）读给我听」由模板生成） | ~2,600 | 学断句体、称谓、口癖 |
| **C 记忆行为** | 模板化：给定「记忆片段 + 用户提问」→ 正确引用 / 说「我记不清了」/ 更新冲突事实 | 500–1,000 | 学记忆的动作，而不是事实 |
| **D lore QA（可选）** | 从 `l3-*.json` / `oracle-fulfillment.v2.json` / `key-events.json` 抽问答对 | 200–400 | 世界知识（也可全交给 RAG） |

**硬约束**：`is_duplicate=true`、`extra`（折叠闲聊）、108 条乱码段、复合说话人（「赛白厄」）先剔除；dev/test 里**不能**出现训练样本原文（防泄漏）。

### 4.2 超参（先写死，P0 实测后再调一次）

```
基座     Qwen3-1.7B（bf16）；如 P0 证实 bnb 可用 → Qwen3-4B-Instruct-2507（4-bit NF4，double quant，compute bf16）
LoRA     r=16, alpha=32, dropout=0.05, target=q/k/v/o/gate/up/down
序列     1024（记忆样本 1536）；batch=1 × grad_accum=16；gradient_checkpointing=on；attention=sdpa
优化     lr=1e-4 cosine, warmup 3%, epochs 2–3, bf16
时间     1.7B LoRA 约 0.5–1 h/epoch；4B QLoRA 约 1.5–2.5 h/epoch（P0 实测为准）
OOM     降级顺序：seq 1024→768→512 → 关 4-bit 试 0.6B → 换 4B 推理-only
```

### 4.3 上线链路

`LoRA merge → HF 目录 → convert_hf_to_gguf.py → Q4_K_M → llama.cpp server / Ollama（`OLLAMA_MODELS=D:\...`）`
→ FastAPI 包一层「记忆中间件」，模型只当「说话的那一半」。

## 5 记忆系统：真正的重点（别全押在微调上）

小模型 + 好记忆 > 大模型 + 没记忆。四层结构，全部落 SQLite + 本地向量：

| 层 | 存什么 | 写入 | 读取 |
|---|---|---|---|
| **L1 工作记忆** | 最近 N 轮原文 | 每轮 | 直接进 prompt；超预算时把最旧的压成摘要 |
| **L2 情景记忆（自传体）** | 每轮事件：时间、谁说的、内容、重要度、情绪标签、所属会话 | 每轮（重要度由规则+模型自评） | 打分排序取 top-k |
| **L3 世界知识（RAG）** | 语料片段、L3 笔记、神谕/事件/泰坦配置 | 离线建库（已有 bge 向量） | bge 检索（+BM25 混合），**回答带 record_id 可回查** |
| **L4 人格/成长状态** | 阶段、关系值、自传《如我所书》版本、已收未用的记忆 | 反思时更新 | 每轮进 system prompt |

**检索打分**（Generative-Agents 式，权重先写死）：
`score = 0.55·cos(bge) + 0.25·recency(半衰期 7 天) + 0.20·importance`，再 MMR 去冗余。

**成长状态机（德谬歌专属，也是最有戏的部分）**：
```
种子(0–20 条记忆) → 幼芽(20–80) → 花蕾(80–200) → 花(200–500) → 心(500+)
```
阶段跃迁时改变三个语气参数：**句长上限 / 逗号密度 / 自称与称谓**（数值直接抄语料统计：迷迷期均长 6.5 字、0.17 逗号/句）。
**「收梢即起始」**：每积累 50 条记忆，反思模块重写一次自传，**旧版本存档不删**——记忆不是只增，而是会被新理解重写。

**Prompt 预算**（token 级，总量控制在 4k 以内，给 8k 上下文留余量）：
`人格 600 + 自传/状态 300 + 检索记忆 800 + 世界知识 600 + 最近对话 1200 + 本轮 → 生成`

## 6 评测：先冻结，再动手

**四格消融（必须全跑，否则不知道钱花在哪）**：
`base（原模型） / +prompt / +LoRA / +记忆 / 全量`

| 维度 | 指标 | 冻结方式 |
|---|---|---|
| 风格像不像 | 均长、逗号率、断句率、称谓命中（桃子/开拓者/灰宝）、口癖命中、自称一致 | 用迷迷语料的统计区间当靶心；50 条 prompt 固定 |
| 记忆 | 植入 20 条事实 → 1/10/50 轮后各问一次；跨会话；冲突更新 | 20 题固定，问法固定 |
| 世界知识 | 50 题（13 神谕 + 13 泰坦 + 关键事件），对 L3 笔记判分；**答错不许编** | 题目与判分口径写进冻结文档 |
| 人味 | 20 段双盲 A/B（人只看「哪个更像德谬歌」） | 两人各判一遍，报一致性 |

> 诚实的边界：1.7B 的逻辑/长文本来就弱，**评测不追 GLUE 式准确率，只追「像 + 记得住 + 不瞎编」**；lore 一律 RAG 兜底，禁止裸生成设定——这条和项目「回到 record_id」的纪律一致。
