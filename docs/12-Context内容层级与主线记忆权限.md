# Context 内容层级、思考依据与主线记忆权限

日期：2026-11-06。本文保存层级与权限设计，记忆首版已实施；当前落点、依赖与验收范围见 [模块说明](../src/core/memory/README.md)。对 [11](11-叙事续接式Context与表现协议.md) 的简略人物材料划分作进一步修正。

后续确认：用户已接受整理线长期使用同一个私有 Session、已授权记忆域内的完整维护权限，以及主线提交叙事理解但不直接覆盖 narrative 的分工；同时确认 L3 允许主线主动回想、检索和展开。上述能力已接入并通过合成模型验证；soul 自动修改范围仍未决，首版只留候选。

## 内容层级

这里的“底层”指人格材料的基础性和稳定性，不等同于取得更多系统权限。运行时的来源、能力、输出协议仍独立约束所有层；soul 中的文字不能增加工具、改变调度或绕过提交。

| 层 | 内容 | 稳定程度与作用 |
|---|---|---|
| L0：soul | 较完整的人物底色、看世界与理解关系的方式、表达材料与重要背景 | 最底层、长期稳定，允许较长；日常经历不直接改写 |
| L1：narrative.md | 积累的自我理解、关系地基、已经生效的取舍与未定看法 | 跨天延续，由整理线根据证据更新；不是再造一套人格设定 |
| L2：当前篇章 | 今天在延续什么、未完成事项、当前处境、相关的近期内省摘要 | 随当日经历变化；状态在这些 context 内容中体现，不增加数值状态表 |
| L3：本次唤起的经历 | 与当前输入相关的具体回忆、原话与证据引用 | 按需检索，有独立预算和访问范围 |
| L4：当前互动 | 近期原生 user / assistant 对话、当前直接输入或已允许的工作观察 | 最接近本次回应，保留说话者和实际顺序 |

L0 提供底色，L1 提供积累，L2 提供当下，L3 提供可追溯的具体材料，L4 承接下一句。这个顺序说明内容职责，不要求每层都成为一条 system message，也不允许把真实对话打平成任意小说续写。

每日首轮为 L0 当前版本 + L1 最新版本 + 上一段交接得到的 L2 + 本次相关 L3 + 必要近期原话与新输入。当天继续轮次不反复重建全部叙事，不把旧快照无限追加。

用户已同意将 L1 单独保存为 `narrative.md`。初始模板位于 [templates/narrative.md](../templates/narrative.md)，暂不填入经历。运行时已生成并加载 `stateDir/narrative.md` 私有投影；版本、来源与取舍依据由原生审计 Session 日志维护，Markdown 不成为另一份权威事实源。模板注释不注入模型。

## narrative 与既有设计的对应关系

`narrative.md` 就是此前 L1“积累的自我与关系叙事”的可读载体，不新增一层 Context，不新增一个整理 Agent，也不复制一份完整记忆库。

| 既有内容 | narrative 与它的关系 |
|---|---|
| L0 soul | 独立的底层人物材料。narrative 记录相处后形成的理解，不逐段复述 soul，也不因更新就自动改变 soul |
| 原生日志与两类思考记录 | narrative 的证据来源；原文和 reasoning / 内省仍各自保留，不把全部原始思考塞进 narrative |
| 事实、偏好、情景记忆与索引 | 保留可查询的具体材料。narrative 只呈现对当前自我 / 关系有持续意义的理解与取舍，不替代这些条目 |
| 整理线的增量任务 | 形成记忆条目与关联；不要求每次抽取都重写 narrative |
| 整理线的反思整合 | 依据经历、思考、已接受记忆和旧 narrative 提出 L1 更新，仍通过既有提交链 |
| L2 当日篇章与跨段交接 | 承载未完话题、临时事项、当前处境和必要短摘要。每天开段直接加载当前 L1，不把它抄入每日交接再重复注入 |
| 日记 / 每日反思产物 | 记录一个时间范围里的回看，可作为 L1 更新材料；不是把每天日记全文追加到 narrative |
| L3 检索与 L4 对话 | 按本次需要补具体证据和近期原话，与 L1 一起进入当前请求，不因 narrative 已概括就删掉唯一原文 |

从证据到载体的关系：

```text
原生 Session 的经历、表达、两类思考与已提交记忆决定
  → 既有整理线的反思整合
  → 校验并提交 narrative 的来源、基准版本和更新结果
  → 渲染当前 narrative.md（L1）
  → Context 在 soul（L0）之后加载该版本
```

文件生成不在提交前取得事实权威；文件被删除或版本不符时，从已提交记录重建，不重跑模型猜一遍过去。来源 / 版本伴随内部提交记录，正文保留可读叙事，维护注释不进入最终模型材料。

### 与压缩、换段和遗忘的联动

- **压缩**更新当前工作 surface，不直接覆盖 L1。narrative 如需精简，仍需形成独立的有来源整理版本，不能拿任意压缩摘要替换。
- **换段**加载同一身份当前的 L0 / L1；交接只额外承接 L2 与必要近期原话，L3 再按需查询。日期变化不清空或复制 narrative。
- **整理更新**替换 L1 的当前视图，不在每轮后追加所有历史版本；旧版本仍可由日志追溯。
- **遗忘 / 禁读 / 更正**要同步核对 narrative 和当前 Context 的残留。不能仅调整索引，却让 L1 或交接继续携带失效内容；旧 narrative 不得覆盖已接受的新更正。
- **主线重要标记**影响整理优先级与允许的保护范围，不直接改写 narrative 正文。整理线独立判定哪些内容已具有跨日意义。
- **soul 变更**可参考 narrative 的长期变化，但另走 L0 变更流程；单独建立 narrative 不代表 soul 被永久冻结，也不代表整理线已经获得自动改写 L0 的权限。

上述职责已接入首版。维护提交使用不运行 Agent 的原生审计 Session，整理模型仍只有一个长期 Session；这解决当前格式不能直接追加任意插件事件的问题，详见模块说明。

## L3 的来源与组装职责

L3 不是另一个需要模型每轮写作的文件，而是本次请求的只读召回结果。职责分为：

1. 整理线平时根据原生日志维护记忆条目、关联、摘要、有效状态与来源；已提交内容进入可重建索引。
2. 请求开始时，检索与组装代码依据当前输入、近期话题和授权范围查询已提交记忆，核对有效版本、访问限制、来源和预算，生成本次 L3。首版不要求等待一次整理模型调用，也不新增一个召回 Agent。
3. 主线拥有主动的只读回想能力，可以根据当前思路决定要查什么、何时补查、是否展开原话或关联经历；不局限于被动接收首轮命中，也不必等待整理线批准。已通过 `memory_recall` 接入，代码检查授权、有效状态、访问限制和预算，不赋予任意文件 / 会话读取权。

因此，主线主动掌握的是本次回想的方向与展开需求；记忆是否真实存在、返回哪些有效版本和读取边界由底层保证。查询结果通过原生只读工具结果或受支持的上下文准入返回，不能由主线伪造为历史证据；结果不足时可以继续有限补查或承认没有找到。被调用的具体次数、预算和协议仍需在实现时验证，不增加另一个维护副本。

已有记忆摘要可以由整理线生成，L3 本轮选择和包装由代码完成；摘录、摘要、原话分别标明，不新编一段故事当作已发生的经历。允许无命中、标明推测与冲突，不用 narrative 中的概括代替唯一原始证据。刚发生且尚未整理的内容仍由 L4 近期原文承接。

## 整理线的长期 Session 与权限范围

用户已确认整理线长期保留同一个私有原生 Session，不按主线的每日边界轮换，也不为每个批次新建一个整理 Session。它保留整理过程、先前取舍和用户与整理线的对话。增量整理、低频反思和维护对话是同一整理线中的任务类型，不增加第三条线。

同一 Session 不代表每次请求装入全部日志，也不表示模型在未调用时持续思考。工作 surface 仍需原生压缩，保留任务位置、未完成决定、必要近期材料与当前版本；历史决定和源片段可按需查回。长期日志的恢复、投影和压缩成本仍需验证，不把“永远单个物理日志且成本不增长”作为已验证保证。

任务与维护对话在该 Session 的执行队列中串行进入；每项保留独立任务类型、来源范围和操作 ID。用户维护指令与后台取舍不冒充主线当时的思考，也不因同处一个日志而全部重新抽取成角色经历。整理任务引用创建时的主线 Session / 事件，不在主线换日后改成新段来源。

用户已接受将“全量权限”限定为完整的**本产品已授权记忆域维护能力**，不授予通用宿主控制权。已确认的范围如下，soul 自动采纳仍单独待定：

| 能力 | 边界 |
|---|---|
| 查询记忆域历史、原话、两类思考、已有取舍和 narrative 版本 | 可跨主线日期段按需读取；查询不等于每次全量注入。整理维护与主线正常召回范围分别检查，明确禁读 / 撤回仍须遵守 |
| 新建、纠正、合并、保护、降权、归档、停止主动召回 | 在允许语义内自主执行，经代码校验提交，不要求主线逐项审批；有效保护与明确用户要求不能静默绕过 |
| 更新 narrative | 有来源、基准版本与操作 ID 的版本化更新；已接受结果写入原生记录后生成当前 Markdown |
| 改动 soul | 可提出有依据的局部候选；自动采纳范围仍未决定，不因扩大记忆维护能力默认开放 |
| 改写原始日志、物理删除、变更授权 / 调度、运行 Shell 或任意读取其他工作区 | 不因“全量记忆权限”而获得；原始事实与维护决定仍分开 |

语义上的决定来自整理线，实际持久提交仍由代码执行。操作范围和版本检查不等于为每次维护增加人工审批。

## 较长 soul 的装配

不再默认 soul 只是几句设定或少量代表文字。首版目标是完整、稳定地放在基础段，标明版本与来源，避免每轮为即时情绪改写，也不因每日换 Session 而重新生成。

实际内容尚未提供，因此不猜 token 数量或冻结长度。用宿主计量基础材料后，为近期对话、召回、输出及必要思考预留预算。压缩工作上下文时不把 soul 自动浓缩成几行；若基础材料本身已使请求无法容纳，需明确调整材料结构 / 模型窗口，不能静默截断。

稳定前缀有利于利用供应商的缓存，但不保证命中或免除 token 窗口占用。DeepSeek 官方文档说明缓存基于前缀匹配且为 best-effort；DSH 路由与实际协议仍须实测，不为了缓存绕过原生消息与调用链。

稳定人物材料是已声明的设定 / 来源材料，不伪装为与当前用户真实发生的经历。L1–L4 也不能通过一次强烈输入反过来直接重写 L0。

## 思考依据需要记录什么

用户要求每日对话保留思考部分，否则只凭台词不足以判断是否应改变 soul。需要区分：实际输入和表达、当时形成的理解、后续整理器重新解释，以及供应商返回的 reasoning。这几者的来源和时间不同。

可回放的显式内省记录建议包含少量高层内容：当前在意什么、如何理解相关经历、哪些看法尚不确定、什么值得留下，以及原话 / 事件引用。它表达“在这一时刻形成了这个看法”，不能证明其中推测为客观事实，也不能凭它单独确认外部事件发生。

不要求每个轮次机械填满同一表格，也不为修改 soul 而补造思考。重要回合可形成短记录，日常整合再结合原文与这些记录复查。后台事后生成的总结必须标明为事后解释，不能补写成主线当时已经想过。

用户已明确选择“两者都保留，用途分开”：宿主可提供的 DeepSeek reasoning 如实保留为原生生成记录；显式的短内省作为整理与跨日理解的结构化材料。两者标明类型、所属 Session / 回合、时间及来源，不互相冒充。

reasoning 用于回看当时实际返回了什么，不表示稳定人格或世界事实；短内省记录当时的高层理解与取舍，便于进入 L1 / L2 的整理。原文、台词、两类思考和后续反思共同形成变更依据，不能只按生成文本的自信程度采纳。主线 context 按需要接收经接受的理解摘要，不无界累积全部 reasoning。

路由未提供 reasoning 时记录缺失，不为凑齐两类材料补造“当时的思考”。显式内省是在何时生成必须真实标注；事后由整理器生成的解释不改写为主线当时的内省。

如果使用供应商 reasoning，应经原生适配器记录和处理其回放，不能把字段随意拼到用户台词。DSH 类型包含 reasoning block / delta 和 attempt 中的 reasoning chunks，但实际选定路由是否完整提供仍需验证。

DeepSeek 的公开文档还区分带 tools 与不带 tools 时的 reasoning 回传行为。当前 DSH DeepSeek 路由可能使用不同线协议，不能直接照搬 OpenAI 格式字段或假定“保存过就会自动成为下一轮记忆”。reasoning 不作为唯一的长期变化依据，不全量注入主线或人格材料。

## 修改 soul 的证据链

每天可以理解和反思，不等于每天修改 L0。建议先在 L1 / L2 记录新的理解与不确定性，跨日复查后才考虑是否构成稳定变化：

```text
真实经历与原话
  → 有来源和时间的思考 / 理解记录
  → 整理线复查重复出现的倾向、反例和过去取舍
  → L1 中可修改的长期理解
  → 必要时提出针对 soul 当前版本的局部变更
  → 校验范围、来源、版本与一致性，保留旧版本
```

变更候选应说明涉及哪个段落、为什么不是一时的情绪或特定说法、有哪些支持和反例。没有足够证据可维持原状，不把“每天完成任务”解释为“每天必须成长”。

整理线提出 soul 变更、是否自动采纳及允许修改哪些底层部分仍是未决边界。当前不开放主线直接编辑 L0，也不默认整篇每日重写。思考载荷已确定双类保留，精确采纳规则需结合这些材料的实际可用性与最终 soul 内容收敛。

## 主线可以获得的有限记忆权限

此前“主线不持有底层写权限”不应被解释为主线对重要经历完全没有影响。用户提出的重要记忆意图，可通过窄能力获得实际效果，但不赋予一般数据库 / 日志访问。

| 能力 | 效果 | 边界 |
|---|---|---|
| 标记当前经历重要 | 追加可追溯的重要意图记录，提升整理优先级 | 来源由程序绑定当前回合 / 已授权可见材料，不接受任意伪造事件 ID |
| 请求临时保留 | 在限定期间或待整理期间保护对应候选，防止被普通自动淘汰流程忽略 | 期限与上限由代码约束；主线不能自行宣布永久保留 |
| 主动回想 / 澄清 | 自主发起已授权记忆查询、补查与原话展开，或提交对记忆理解的更正意愿 | 查询无需整理线逐次批准；不读取任意文件 / 会话，不直接覆盖既有事实 |
| 放下或长期保护的意愿 | 进入整理线有依据的取舍流程 | 不是永久删除、永久冻结或改写 soul 的命令 |
| 提交自己的叙事理解 | 追加带来源和真实时间的短理解记录，作为 L1 更新材料；相关内容可进入后续 L2 | 不直接覆盖 narrative 正文；“我理解成这样”不能作为用户事实或长期共同约定自动成立 |

标记与短期保护在合法性检查和持久化后直接生效，不必等待一次完整的日记 / 整合任务。首版已接入这些窄能力；最终记忆内容、长期生命周期与底层人物变更仍分别处理。

普通台词中的“我记住了”不通过文本关键词直接执行。意图应进入与正文、动作分开的受限通道，并在对应原生消息 / attempt 确定保留后绑定真实来源。不能从用户引用、故事材料或模型随意填写的 JSON 中授予能力。

允许能力可以通过原生受限工具或专有意图协议承载，具体实现需比较原生循环和流式语义；不因命名为“意图”就忽略校验和副作用。quota、重复、取消、失败与重试都需明确。重要标记只是角色对此刻材料的重视，不自动证明材料描述的客观事实。

整理线仍可自主遗忘与整理，不等待主线授权。已有的临时保护和真正长期保护分别遵守有效范围，不能被常规压缩清除；主线临时标记也不能无限阻断后续整理。

### 主线与 narrative 的写入关系

用户已确认：主线拥有提交叙事理解的窄能力，没有直接编辑 L1 正文的权限。主线通过 `memory_reflect` 记录此刻真实形成的简短理解，相关记录可供后续 L2 承接，由整理线判断是否具有跨日意义并合入 L1。首版已接入 narrative 和受限记忆工具。

不额外建立一份“主线 narrative”或候选 Markdown。理解记录复用既有内省 / 意图持久通道，带来源、时间、状态与去重信息；整理线可以采纳、保留为未定看法或暂不纳入，不能把主线推测升级成外部事实。这样主线能影响自己的长期叙事，已接受 narrative 仍只有同一条版本化更新路径，避免主线与整理线相互覆盖。

## 仍保持的边界

- 不增加独立情绪 / 信任数值模块。思考与叙事是有来源的 context 材料。
- 初始 soul 和记忆仍预留，本轮不擅自补写角色内容。
- 15 秒主动表达门控、Session 分段和用户与整理线对话的方案不变。
- 动作仅预留接口，不将思考或记忆权限混入前端动作通道。
- 思考记录、记忆标记、soul 变更都需走原生 Session 的可靠持久承载；此前的接口未决问题仍然存在。

## 证据与验证范围

实现使用本机 `dsh-system-prompt`、原生 reasoning / compact stream、tools 注册与 guard、token-meter / compaction-basic、持久化 handle 契约。模型桥和工具层分别只放行各自的记忆工具，原始维护记录与用户维护对话不会注入主线；原生模型元信息及辅助压缩预算也沿宿主路由处理。没有运行真实 API。

合成验收覆盖主动召回、理解提交、来源伪造、保护、版本冲突、取消、恢复、Context 撤回、跨日回执和原生压缩。真实整理质量、长 soul 的实际预算和超长日志性能仍需实测；soul 自动变更未启用。具体命令及限制以模块说明为准。
