# 完整 PMX 骨架与表情适配方案

日期：2026-11-07。状态：静态分析、公开源码与发布包调研；未安装引擎或运行实际渲染。依赖 [15](15-本地角色模型检查与MMD适配.md)、[16](16-AIRI接入与动作来源调研.md)、[17](17-上身动作与HAST行为控制复核.md)。本文细化并修正此前“采用 AIRI 底层即可适配”的判断，执行器选择尚未冻结。

## 结论与边界

保留完整原始 PMX，不为匹配 HAST 删除骨骼、重新蒙皮或强制转换成 VRM。HAST 的标准人形运动空间与模型实际骨架之间增加角色专用映射；面部另用本模型的 Morph 配方和冲突控制。骨骼数量不必相同，但参考姿态、空间、控制关系和执行顺序必须适配。

HAST 的行为控制 / 局部轨道、学习运动底座、全身约束求解器是三种不同的接入范围。先复用行为控制与轨道机制；完整学习底座需要保持原 53 骨骼数据契约，全身求解器不直接检查或写入原 PMX 的 493 骨骼。

## 本地模型新增证据

只读分析 `CharacterModel/` 内原文件。私有报告 `.local/character-rig-analysis.json` 仅保存控制关系和统计，不输出顶点坐标、贴图或转换资产；与此前扫描核对全部骨名 / Morph 名与类型、数量及文件末尾一致。

| 项目 | 静态结果 | 适配意义 |
|---|---|---|
| 骨骼 | 493 | 包含控制、蒙皮、辅助、物理等用途，不等于 493 个需由 HAST 独立预测的关节 |
| 实际非零蒙皮引用的骨骼 | 374 | 统计阈值为权重大于 `1e-6`；没有直接蒙皮引用的控制骨仍可能很重要 |
| 绑定动态 / 混合刚体的不同骨骼 | 332 | 不应由动作网络每帧任意覆盖；物理开销需要实测。用途分类可重叠，不能将该数与其他分类简单相加 |
| 继承变换 | 24 | 有负比例补偿、捩骨分配、足 D 骨与眼部继承，需遵循原文件定义 |
| IK / 固定轴 | 4 / 4 | 不能将这些控制骨当成普通关节直接复制旋转 |
| 表情 | 81 个顶点 Morph + 3 个材质 Morph | 当前文件没有骨骼 / 分组 / UV Morph；本轮适配不必先实现所有可能的 PMX 表情类型 |

具体控制链：

- 躯干有 `上半身 → 上半身1 → 上半身2`，不能只选一个写入后便假定其余效果等同。
- 手臂包含肩 P / C、补偿骨、腕捩和手捩。手捩辅助骨已有 0.25 / 0.5 / 0.75 的继承比例，肩部另有负比例补偿；不能再人为重复分配相同旋转。
- `右足 / 右ひざ / 右足首` 等控制链没有直接非零蒙皮引用，`右足D / 右ひざD / 右足首D` 等变形链继承它们并承担蒙皮。左侧类似。不能因为控制骨不蒙皮就忽略它，也不能同时给控制链和 D 链写同一目标旋转。
- `両目` 驱动 `左目 / 右目`，后面还有带负比例继承且实际蒙皮的 `目先`。此前 AIRI 在 MMD 更新后覆写单眼骨的通用视线方式，需要针对本模型调整到正确的输入阶段，避免下游继承使用旧姿态。

## 身体适配：标准控制空间与原生变形骨架分开

```text
DSH 有效主线事件
    → HAST 风格行为控制 / 局部轨道
    → 标准人形目标姿态（需要原学习底座时保留其 53 骨骼顺序）
    → 昔涟专用驱动映射
    → 原始 PMX 控制输入
    → 单一 MMD 执行器：继承变换、IK、物理与变形
```

标准人形是运行内存中的控制空间，不是另一个显示模型，不要求转换、上传或重新导出昔涟。不能伪造一个不完整 VRM 对象绕过 HAST 的检查：涉及原有 VRM 控制器的模块必须明确替换适配边界。

驱动映射分为：

1. **空间标定。** 记录源 / 目标参考姿态、局部轴、朝向、单位和根位置含义。按校准后的姿态目标计算 PMX 控制输入，不直接复制欧拉角或仅按名字复制 quaternion。
2. **控制链分配。** 躯干旋转沿实际脊柱链分配，髋部目标按中心 / 腰 / 下半身的原控制关系处理；手臂需要将摆动和轴向扭转分开，送到相应主骨与捩骨。分配比例需校准，不预先一律均分。
3. **单一控制权。** 主控骨接收目标；继承辅助骨由 MMD 原生求值；动态骨由物理管理；无来源、无原生约束的可选骨保持参考姿态或由明确的局部细节轨道驱动。不能承诺剩余所有骨骼会“自动正确动起来”。
4. **腿部支撑。** 默认原地，髋部可以小幅变化；站姿维护支撑脚目标，单腿小幅摆动明确摆动侧 / 支撑侧并平滑落回。按片段明确 IK / FK 策略，避免 HAST 关节求解后又被 MMD IK 改写同一任务。网页锚点固定不等于髋部和膝盖冻结。
5. **学习策略反馈。** 若进一步采用依赖姿态历史的原学习策略，需要将实际已执行的主关节姿态投回校准的标准空间；不能把 493 骨骼数组或含物理裙摆的姿态直接作为其输入，也不能仅用未执行的目标冒充实际反馈。

目标执行器必须有明确、可验证的输入时机：动画混合后、相关 IK / 继承变换前写入程序控制目标。没有相应公开写入点时，先通过同一 mixer 的目标 AnimationClip 接入，或单独验证适配钩子；不能对整套 helper 每帧调用两次以碰运气消除覆盖。

基础程序动作和已校准的 MMD 动作可以直接使用 PMX 控制空间，不必为了统一接口先绕一遍标准人形。HAST 适配桥只在来源确实使用该空间时参与，同一片段不可既走原生目标轨道又重复重定向。

## 面部适配：语义配方、部位与覆盖规则

HAST 的额外表情在 `face/details.mjs`、`v9_profile.mjs` 中绑定特定 VRM 形态键，如 `mouth_smile_1`、`eyebrow_up_L`；本模型的日语 / 中文 Morph 不能通过换成同长度数组获得相同语义。也没有必要为了聊天表情先拟合完整 ARKit 52 维面部。

建议保留有限语义输入，使用本角色专用的组合配方。能力包括整体表情、眨眼 / 单眼、视线、音频口型、材质效果；各自记录影响部位、强度曲线、进入 / 退出时间、互斥项和口型 / 眨眼 / 视线覆盖策略。VRM Expression 的 override 机制可作设计参考，不要求输出或转换为 VRM。

| 语义 / 部位 | 实际存在的候选 | 需要注意 |
|---|---|---|
| 嘴部微笑 | `口角上げ`、`にやり` 等 | 要在实际形变中确定温和微笑的幅度；不能将所有名字带“笑”的 Morph 等同于嘴角上扬 |
| 笑眼 / 温和眼神 | `笑い`、`慈愛`、`慈愛2` 等 | 与眨眼协调；候选名称不等于已验收的人设表现 |
| 眨眼与单眼 | `まばたき`、`ウィンク`、`ウィンク右` 等 | 双眼关闭与左右关闭只保留一个合成结果，避免同侧重复叠加 |
| 口型 | `あ / い / う / え / お` 等 | 可接标准五元音，但强度及与微笑的混合需标定；跟随实际音频，不按 token 驱动 |
| 材质效果 | `照れ`、`目影濃`、`目影消` | 必须通过材质 Morph 求值，不是只写 vertex morph 权重就一定有效 |
| 装饰性形变 | `脸红`、`涙`、`はぁと`、`星目 ` 等 | 与材质红晕不是同一个通道；按实际显示效果启用，不将特效默认加入日常表情 |

新增的顶点影响统计：

- `笑い` 与 `まばたき` 共享 1,046 个非零影响顶点，与 `口角上げ`、`あ` 的非零影响顶点没有重叠。这支持将其首先作为笑眼候选检查，不能拿通用 smile 槽直接认定已完成面部微笑。
- `口角上げ` 的 565 个非零影响顶点均落在 `あ` 的影响集合内；`怒った2` 与 `あ` 共享 1,046 个顶点。口型与这些嘴部表情需协调预算或按配方抑制。
- 共享顶点只是潜在相互影响的证据，不证明两种 Morph 必须互斥；无重叠也不保证视觉组合自然。最终以实际渲染确定强度和优先级。
- 三个材质 Morph 的实际目标：`目影濃` 对“目影”材质作加算，`目影消` 对同材质作乘算，`照れ` 对“颜+”材质作加算。必须按 PMX 运算求值并在归零时恢复基础材质，不能用统一透明度代替。

一个表情可同时包含嘴角、眉眼和可选材质目标，但不在此刻写死配方权重。先逐个检查，再检验“笑眼 + 眨眼”“微笑 + 五元音”“脸红形变 + 材质照れ”组合。缺少单侧控制等能力时标记限制，不用全脸组合冒充独立通道。

所有来源先经过一个面部合成器再交给执行器，包括 VMD 表情、语义表情、眨眼和音频口型。避免四套模块最后各写一次 influences，依靠更新顺序决定胜负。表现参数只在前端运行，不写成长期情绪数值。

## 可执行的验证顺序

1. **原生 PMX 基线。** 不接 HAST，验证骨架 / 材质、全部 84 个 Morph 的单项渐变和归零，以及眼部继承；物理先关后开。这样能区分加载器问题和重定向问题。
2. **控制链动作。** 分别测试抬臂、前臂扭转、躯干侧倾、小幅重心转移、单腿轻摆；检查肩部塌陷、重复扭转、足 D 链、脚滑、膝盖与裙摆。
3. **表情合成。** 检查闭眼与笑眼、嘴角与元音、材质效果与归零、VMD 表情接管及停止；未校准配方不向主线宣称可用。
4. **HAST 适配桥。** 同一简单动作经标准姿态输入与原生 PMX 输入作比较，核对动作末端、过渡与取消；需要原学习策略时再验证反馈和权重契约。
5. **DSH 常驻。** 根级浮层生命周期不变，测量 CPU / GPU / 物理开销、页面隐藏恢复和切换工作区，确认主线隔离与播放去重。

尚未完成的关键工作是上述实际渲染与视觉校准；静态解析成功不能代替它。模型、贴图、转换产物继续保存在被忽略的本地目录，不上传或随包分发。
