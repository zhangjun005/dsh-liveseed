# 动作衔接与 AI 关键帧方案

日期：2026-11-07。状态：机制复核与设计建议，未实现。约束（用户同日明确）：**只走 AI 关键帧制作路线**；不考虑视频 / 摄像头动捕，也不引入需要大显存的生成式动作模型。依赖 [16](16-AIRI接入与动作来源调研.md)、[17](17-上身动作与HAST行为控制复核.md)、[19](19-PMX常驻舞台首版与验收.md)、[20](20-动作生成路线调研.md)。

## 当前实现的问题

`pose.ts` 现在是"单手势 + 全局包络 + 固定平滑"：

- 同一时刻只有一个 `active` 手势；切换时直接替换并重置计时。
- 每个手势都从同一份 authored 中立姿态起止，因此**连续两个动作之间必然经过中立姿态**，看起来像断一下。
- `smooth()` 是帧率相关的指数低通（约 20/s），不是计划好的过渡：角距大时偏慢，角距小时偏拖。
- `stop` 固定 0.35 秒淡出，与当前姿态的实际角距无关。
- 不能叠加：挥手与点头互斥；没有 mask、优先级、冲突仲裁。
- 没有表现状态机：待机、聆听、说话、执行手势没有区分，也没有锁定与排队。

## AIRI 与 HAST 的实际差别

- **AIRI**（[16](16-AIRI接入与动作来源调研.md) 已核对）：animation-manager 只有动作注册、单次 / 循环播放、全局淡入淡出、结束回 idle。**没有分层、冲突仲裁、优先级和状态机**，所以动作衔接只能是整段交叉淡入淡出，两个动作会互相覆盖。
- **HAST-SEC**（[17](17-上身动作与HAST行为控制复核.md) 已核对，固定提交 `f4d5c9aa`）：所谓"状态机"实际是三个独立机制，不是可整体搬走的 FSM 包：
  - `motion/base_policy.mjs`：intent + speaking / listening + `locked` / `queued`。局部动作期间**只锁基础原型切换**，不缩放未覆盖关节、不改骨骼姿态。
  - `motion/beat_layers.mjs`：轨道声明 `mask`；每轨从固定来源读取**绝对局部旋转**，不在执行结果上累加；权重用五次 smoothstep 包络；**淡入淡出时长按实际角距分配**；mask 冲突时旧轨从当前权重淡出；循环用首尾角距处理接缝；轨道数与参数有界（≤16 轨）。
  - `motion/contact_state.mjs`：脚部支撑 / 卸载 / 落回状态，供下半身小幅摆动使用。
- 所以"用 HAST 的状态机"落地时是**借这三类机制、自己写实现**。其代码为非商业学习研究许可，不能直接并入本插件。

## 关键对应关系

Live2D 里"参数 + 贝塞尔曲线"在 3D 的等价物就是**关节目标曲线 + 分层权重混合**，不需要网格变形那一步。而 AI 手 K 的产物也不该是一段代码，而应是**关键帧数据**：模型只负责"做什么动作、到什么姿态、用多久、缓动如何"，运行时负责校验、混合与求值。这样两侧边界清楚，也便于离线审校。

## 建议方案

### 1. 动作数据模型（AI 关键帧的产物）

```text
Gesture {
  id, part: head|arm|torso|leg,
  mask: ['首','頭'],                     // 只允许写入列表内骨骼
  keys: [{ t, pose: { joint: euler } , easing }],
  loop: false,
  exit: 'blend' | 'hold'
}
```

- 可选语义层（给模型用）：MPL 式 `arm_r raise up 45`、`head bend forward 5`，由校验器翻译为关节旋转。
- 校验：骨骼白名单（排除 IK 骨、物理骨、派生骨）、角度上限、时长范围、mask 与 part 一致、不得触碰 MMD 求解链负责的部分。

### 2. 运行时混合器（核心，替代现在的 `smooth()`）

- **分层**：base（呼吸 / 视线 / 待机，每帧从 authored 基线重算）+ 每个手势一条 track。
- **混合**：按 mask 收集各轨目标旋转，权重归一化后逐级 slerp；未覆盖的关节保持 base。
- **过渡时长按角距**：`fade = clamp(1.875 × 关节最大角距 / 角速度上限, 0.35, 1.2)`。五次 smoothstep 的最大导数为 1.875，这样峰值过渡速度有界：大动作过渡更长，小动作不拖。
- **冲突**：新 track 与旧 track 的 mask 相交时，旧轨从**当前权重**开始淡出（cancelWeight），新轨同时淡入，不硬切。
- **中断 / 停止**：统一走"淡出到 base"，时长同样按当前角距计算。
- **循环**：用首尾姿态角距决定循环淡入窗。
- **边界**：≤16 轨、`dt` 上限、参数范围校验，非法输入拒绝而不是猜。

### 3. 表现状态机（表现层，不是情绪 / 记忆）

- 状态：`idle | listening | speaking | gesture | recover`；带 intent 队列与 `locked`。
- 手势执行期间锁住 base 原型切换，但呼吸、视线等不冲突通道继续。
- 事件来源：真实音频播放 → `speaking` / 口型；主线回复开始与结束 → 手势候选；停止 / 取消 → 淡出。
- 不移植 HAST 的主动聊天触发；主动表达仍受普通工作 prompt 后 15 秒窗口约束；整理线与后台任务不得触发表现。

### 4. AI 关键帧管线

- 主线在已授权的"有限表现意图"范围内给出动作意图（[12](12-Context内容层级与主线记忆权限.md)），落为语义脚本 → 校验 → 关键帧 → 混合器执行。
- 运行时只播放**已验收**的脚本，不在运行期调用动作生成模型（用户已排除大显存路线与视频动捕）。
- 离线制作：模型产出候选 → 人工审校 → 入库。参考 MPL 的语法形态但自写解析器，避免 GPL 代码并入。

### 5. 分步落地

1. 把现有 5 个程序手势改成关键帧数据 + 新混合器（动作意图不变，只换过渡），先解决"动作之间断一下"。
2. 状态机外壳 + idle / listening / speaking 接线。
3. 语义脚本 DSL、校验器与模型产出流程。
4. 口型：只在真实音频事件下驱动 Morph。

## 验收

- 数值：角距 → fade 单调递增；同骨多轨权重和为 1；冲突淡出时相邻帧角度差有界；停止后归位；无累积旋转；不写派生骨 / IK 骨。
- 视觉：连续两个手势切换，逐帧截图无跳变。
- 现有 `scripts/testing/character.test.mjs` 的姿态回归检查可扩展为上述断言。
- 表现不写回记忆 / 情绪；整理线不触发播放。
